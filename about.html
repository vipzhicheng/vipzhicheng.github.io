关于本站

本站的目的是梳理和总结一些全栈开发相关的知识点和相关资源，方便自己在工作中查阅，如果也能对你有用就再好不过了。本站的核心知识点章节均来自于 AI 生成，因为 AI 总结的比我好，而且随着时间的推移，技术的演进，我可以用 AI 重新生成以包含技术的最新进展。

建站思路​

一直以来我都想尝试建立一个知识库+博客类型的站点，因为纯博客原创压力太大，还是知识库+博客这种比较好，因为知识库我可以慢慢打造，没有时间线的限制和压力。相对来说也访客也更有价值。如果有观点和想法我会写成博客。如果是知识类，应该以某种结构化的形式呈现在知识库。

技术选型​

本站的建设极大的参考了 https://spacexcode.com/ 这个知识库+博客，因为做的确实很用心。也参考了一些其他知识库+博客的站点或者纯知识库的站点。

建站框架​

选择的是 Docusaurus 这个框架，这里确实纠结了一阵子，因为现在的可选项还是很多的，我比较看重灵活的路由和扩展性，还有可以支持动态页面和 mdx 格式的 Markdown 和组件混写。在这些需求下，选择项就不是那么多了，但仍然可以选 Nuxt, Next，以及 Docusaurus 我选择了 Docusaurus，因为其他两个框架太灵活，而 Docusaurus 是专门会文档+博客而生的，很适合我的需求。

内容板块​

  • 知识库
  • 博客
  • 博客译站 (建设中)
  • 专题
  • 作品集
  • Newsletter (建设中)

这里博客译站是另一套博客系统，用来翻译一些国外的优秀文章。都是搬运+AI 翻译，我想只要选择的是优秀文章，并且 AI 翻译准确，那么价值就会很大。而能支持双 Blog 系统并存也是 Docusaurus 的一大特色。

架构和服务器​

本站采用双 Repo 的形式，全都托管在 Github 上，源码是 private 仓库，编译后成品放在 public 仓库，并且每次 private 推送利用 Github Actions 自动编译，推送到 public 仓库。Github Pages 直接托管在 Github 上。

我看很多直接使用 Github Repo 当博客的大佬，一般都要备注一下，欢迎 Star，不要 Fork，很尴尬，所以后来都把博客用 Issues 来写了，这样别人就 Fork 不走了。这个双 Repo 的模式可以很好的解决这个问题。另一个问题是持续运营的问题，一般博客站都会在某个时间点，因为各种各样的原因不想续费买服务器而停止运营，我收藏的很多博客现在都打不开了。这种双 Repo 的模式也最大化的保证了持久运营的能力，Github 不倒我不倒。

使用 Github Pages 的好处

  • 免费
  • 全球 CDN
  • 域名可以自定义
  • SSL 证书自动申请
  • 支持 HTTPS
  • 支持自动化构建

也说说缺点

  • Github Pages 的 CDN 速度不如国内的 CDN 快
  • 可能存在打不开的风险
