Drupal 10+ 核心知识点

1. Drupal 简介与核心理念​

1.1 什么是 Drupal？​

Drupal 是一个用 PHP 编写的开源内容管理系统 (CMS) 和内容管理框架 (CMF)。它以其灵活性、可扩展性和强大的社区支持而闻名，适用于构建从简单博客到复杂企业级应用程序的各种网站。Drupal 10+ 基于 Symfony 框架构建，采用了现代 PHP 实践和面向对象编程。

1.2 核心理念​

  • 模块化 (Modularity): 功能通过核心模块和贡献模块（以及自定义模块）添加。核心提供基础，模块扩展功能。
  • 实体系统 (Entity System): 结构化内容（节点、用户、分类术语等）和配置的核心抽象层。几乎所有数据都是实体。
  • 字段 API (Field API): 允许将不同类型的数据字段（文本、数字、引用等）附加到实体上，实现数据的结构化。
  • 配置管理 (Configuration Management): 基于 YAML 文件管理站点配置（如内容类型、视图、系统设置），便于部署和版本控制。
  • 插件系统 (Plugin System): 提供可发现、可插拔、可重用的组件（如块、字段类型、视图显示、动作等）。
  • 服务容器 (Service Container - 基于 Symfony): 管理对象的创建和依赖注入 (DI)，促进代码解耦和可测试性。
  • 路由系统 (Routing System - 基于 Symfony): 将 URL 请求映射到控制器 (Controller) 来处理并返回响应。
  • 事件系统 (Event System - 基于 Symfony): 允许模块监听和响应系统中发生的特定事件，实现更灵活的解耦交互。
  • 主题系统 (Theming System): 使用 Twig 模板引擎分离表现逻辑 (HTML/CSS/JS) 与业务逻辑 (PHP)。后端开发者主要关注数据准备和预处理。
  • 缓存系统 (Caching System): 多层缓存机制（页面、动态页面、渲染、数据等），依赖缓存标签和上下文进行智能失效，以提高性能。
  • 钩子系统 (Hooks - 逐步减少但仍存在): Drupal 传统的扩展机制，允许模块在特定事件点修改或扩展核心及其他模块的行为。新开发中优先考虑事件和插件。

2. 环境与安装​

2.1 系统要求​

  • Web 服务器 (Apache, Nginx) - 需要支持 URL 重写。
  • 数据库 (MySQL/MariaDB, PostgreSQL, SQLite) - MySQL/MariaDB 最常用。
  • PHP (版本要求见 Drupal 官网，Drupal 10.1+ 需要 PHP 8.1+，建议 8.2+) - 需要特定 PHP 扩展 (如 PDO, GD, XML, JSON, MBstring)。
  • Composer 2+ (PHP 依赖管理工具，安装和管理 Drupal 的必须工具)。

2.2 安装方式​

  • 推荐方式: 使用 Composer 创建项目

    # 创建 Drupal 推荐的项目结构，包含核心、依赖和基本目录结构
    composer create-project drupal/recommended-project my_drupal_site

    cd my_drupal_site
    # vendor 目录包含所有依赖，web 目录是 web 服务器的根目录

    # 接下来可以通过浏览器访问进行安装，或使用 Drush

  • 使用 Drush (Drupal Shell) 进行安装 (命令行)

    # 在项目目录下 (my_drupal_site)

    # 示例：使用 MySQL
    # drush site:install standard --db-url=mysql://db_user:db_pass@127.0.0.1/db_name --site-name="My Drupal Site" --account-name=admin --account-pass=your_secure_password

    # 示例：使用 SQLite (适合本地开发)
    # 确保 SQLite PHP 扩展已启用
    drush site:install standard --db-url=sqlite://../drupal.sqlite --site-name="My Local Site" --account-name=admin --account-pass=password

3. 核心架构 (基于 Symfony)​

Drupal 10+ 深度整合了 Symfony 框架的核心组件，这是理解其内部工作方式的关键。

3.1 Symfony 组件​

Drupal 使用了如 HttpFoundation (处理请求/响应), HttpKernel (请求处理流程), Routing (URL 映射), EventDispatcher (事件机制), DependencyInjection (服务容器), Yaml (配置文件解析), Serializer (数据序列化) 等关键 Symfony 组件。

3.2 服务容器 (Service Container) & 依赖注入 (DI)​

服务是完成特定任务的可重用对象（如数据库连接、日志记录器、实体管理器）。服务容器负责创建和管理这些服务及其依赖关系。依赖注入是将服务（依赖）传递给需要它们的对象（通常通过构造函数）的过程，而不是让对象自己创建依赖。

  • 定义服务: 在模块的 my_module.services.yml 文件中定义。
  • 获取服务:
    • 静态方法 (应尽量少用，主要用于旧代码或无法注入的场景): \Drupal::service('service_id');
    • 推荐: 通过构造函数注入到类（如 Controller, Form, Plugin, EventSubscriber）中。
    • 对于实现了 ContainerInjectionInterface 的类 (如 ControllerBase, FormBase)，通过 create() 静态方法从容器获取服务并注入。
# modules/custom/my_module/my_module.services.yml
services:
  # 定义一个名为 my_module.custom_logic 的服务
  my_module.custom_logic:
    # 指定实现该服务的类
    class: Drupal\my_module\Service\CustomLogicService
    # 定义构造函数参数（依赖的其他服务）
    arguments:
      ["@database", "@logger.channel.my_module", "@entity_type.manager"]

  # 定义一个日志通道，用于记录本模块的日志
  logger.channel.my_module:
    parent: logger.channel_base # 继承基础日志通道服务
    arguments: ["my_module"] # 指定通道名称
// modules/custom/my_module/src/Service/CustomLogicService.php
namespace Drupal\my_module\Service;

use Drupal\Core\Database\Connection;
use Drupal\Core\Entity\EntityTypeManagerInterface;
use Psr\Log\LoggerInterface; // 使用 PSR-3 日志接口

class CustomLogicService {

  protected $database;
  protected $logger;
  protected $entityTypeManager;

  /**
   * 构造函数，通过类型提示接收注入的服务.
   */
  public function __construct(Connection $database, LoggerInterface $logger, EntityTypeManagerInterface $entityTypeManager) {
    $this->database = $database;
    $this->logger = $logger;
    $this->entityTypeManager = $entityTypeManager;
  }

  /**
   * 执行一些自定义逻辑.
   */
  public function performAction(int $userId): bool {
    try {
      $user = $this->entityTypeManager->getStorage('user')->load($userId);
      if ($user) {
        // 示例：使用数据库服务执行查询
        $query = $this->database->select('my_custom_table', 'mct')
          ->fields('mct', ['data'])
          ->condition('uid', $userId)
          ->execute();
        $result = $query->fetchField();

        $this->logger->info('Action performed for user @uid with result: @result', ['@uid' => $userId, '@result' => $result ?? 'N/A']);
        return true;
      }
      else {
        $this->logger->warning('User with ID @uid not found for action.', ['@uid' => $userId]);
        return false;
      }
    } catch (\Exception $e) {
      $this->logger->error('Error performing action for user @uid: @message', [
        '@uid' => $userId,
        '@message' => $e->getMessage(),
      ]);
      return false;
    }
  }
}

// $service = \Drupal::service('my_module.custom_logic');
// $service->performAction(1);

3.3 路由系统 (Routing)​

将 HTTP 请求的 URL 路径映射到相应的控制器方法来处理。路由在 my_module.routing.yml 文件中定义。

# modules/custom/my_module/my_module.routing.yml
my_module.admin_settings:
  path: "/admin/config/my-module/settings"
  defaults:
    # 指向一个实现了 FormInterface 的表单类
    _form: '\Drupal\my_module\Form\MyModuleSettingsForm'
    _title: "My Module Settings" # 页面标题
  requirements:
    # 要求用户拥有 'configure my module' 权限才能访问
    _permission: "configure my module"

my_module.user_data:
  path: "/user/{user}/my-data" # 包含参数，{user} 会自动进行实体加载
  defaults:
    # 指向一个控制器类的方法
    _controller: '\Drupal\my_module\Controller\UserDataController::showData'
    _title_callback: '\Drupal\my_module\Controller\UserDataController::getTitle' # 动态标题
  requirements:
    _entity_access: "user.view" # 要求对传递的用户实体有 view 权限
    # _permission: 'access user profiles' # 也可以用普通权限
  options:
    parameters: # 定义参数的类型，{user} 自动识别为用户实体
      user:
        type: entity:user # 指定参数是用户实体
// modules/custom/my_module/src/Controller/UserDataController.php
namespace Drupal\my_module\Controller;

use Drupal\Core\Controller\ControllerBase;
use Drupal\user\UserInterface; // 类型提示用户实体
use Symfony\Component\DependencyInjection\ContainerInterface; // 用于依赖注入
use Drupal\my_module\Service\CustomLogicService; // 假设使用之前的服务

class UserDataController extends ControllerBase {

  protected $customLogicService;

  public function __construct(CustomLogicService $customLogicService) {
    $this->customLogicService = $customLogicService;
  }

  // 使用 create 方法进行依赖注入
  public static function create(ContainerInterface $container) {
    return new static(
      $container->get('my_module.custom_logic')
    );
  }

  /**
   * 显示用户相关数据.
   *
   * @param \Drupal\user\UserInterface $user
   *   从路由参数自动加载的用户实体对象.
   *
   * @return array
   *   一个渲染数组.
   */
  public function showData(UserInterface $user) {
    // 使用注入的服务
    $this->customLogicService->performAction($user->id());

    $build = [];
    $build['intro'] = [
      '#markup' => $this->t('Showing custom data for user @name.', ['@name' => $user->getAccountName()]),
    ];
    // ... 添加更多数据到 $build ...
    $build['#cache']['tags'] = $user->getCacheTags(); // 添加缓存标签

    return $build;
  }

  /**
   * 为页面提供动态标题.
   */
  public function getTitle(UserInterface $user) {
    return $this->t('Custom Data for @name', ['@name' => $user->getAccountName()]);
  }
}

3.4 事件系统 (Event System)​

允许模块在特定事件发生时执行代码，实现解耦。订阅者在 my_module.services.yml 中标记 event_subscriber 标签。

# modules/custom/my_module/my_module.services.yml
services:
  my_module.user_login_subscriber:
    class: Drupal\my_module\EventSubscriber\UserLoginSubscriber
    arguments: ["@messenger", "@logger.channel.my_module"]
    tags:
      - { name: event_subscriber }
// modules/custom/my_module/src/EventSubscriber/UserLoginSubscriber.php
namespace Drupal\my_module\EventSubscriber;

use Symfony\Component\EventDispatcher\EventSubscriberInterface;
use Symfony\Component\HttpKernel\KernelEvents; // Symfony 事件
use Drupal\Core\Session\AccountEvents; // Drupal 核心事件 (较少使用，优先使用 Symfony)
use Symfony\Component\HttpKernel\Event\RequestEvent; // 请求事件类型
use Drupal\Core\Messenger\MessengerInterface;
use Psr\Log\LoggerInterface;
use Drupal\user\UserAuthInterface; // 用于获取登录用户（但事件对象通常已包含）

class UserLoginSubscriber implements EventSubscriberInterface {

  protected $messenger;
  protected $logger;

  public function __construct(MessengerInterface $messenger, LoggerInterface $logger) {
    $this->messenger = $messenger;
    $this->logger = $logger;
  }

  /**
   * {@inheritdoc}
   */
  public static function getSubscribedEvents() {
    // 监听用户登录事件 (来自 user 模块的自定义事件，或 KernelEvents::REQUEST)
    // 更好的方式是监听 Symfony 的 SecurityEvents::INTERACTIVE_LOGIN (如果使用了 Symfony Security)
    // 这里用 KernelEvents::REQUEST 作为示例，实际登录处理更复杂
    $events[KernelEvents::REQUEST][] = ['onUserLoginMaybe', 30]; // 示例: 检查请求
    return $events;
  }

  /**
   * 示例：在请求早期检查是否是登录后的用户.
   * 注意: 实际登录事件处理通常更复杂，涉及 Security 组件事件.
   */
  public function onUserLoginMaybe(RequestEvent $event) {
    // 获取当前用户
    $account = \Drupal::currentUser();
    if ($account->isAuthenticated() && !$account->isAnonymous() && $event->isMainRequest()) {

        // 例如，检查上次登录时间，显示特定消息等

3.5 插件系统 (Plugin System)​

用于创建可互换的功能单元。后端开发者常创建或使用 Block 插件、Field Type/Widget/Formatter 插件、Action 插件、Queue Worker 插件等。

  • 定义: 通过注解 (@PluginId(...)) 标记类，实现特定插件类型的接口。
  • 管理器: 每个插件类型都有一个管理器服务（如 @plugin.manager.block）用于发现和实例化插件。
  • 依赖注入: 实现 ContainerFactoryPluginInterface 以在插件中进行依赖注入。
// 示例：创建自定义队列处理器 (Queue Worker) 插件
// modules/custom/my_module/src/Plugin/QueueWorker/MyDataProcessor.php
namespace Drupal\my_module\Plugin\QueueWorker;

use Drupal\Core\Queue\QueueWorkerBase;
use Drupal\Core\Plugin\ContainerFactoryPluginInterface;
use Symfony\Component\DependencyInjection\ContainerInterface;
use Drupal\Core\Database\Connection; // 注入数据库服务
use Psr\Log\LoggerInterface; // 注入日志服务

/**
 * Processes items in the my_module_data_queue.
 *
 * @QueueWorker(
 *   id = "my_module_data_processor",
 *   title = @Translation("My Module Data Processor"),
 *   cron = {"time" = 60} // 表示该队列期望每 60 秒左右通过 cron 处理一次
 * )
 */
class MyDataProcessor extends QueueWorkerBase implements ContainerFactoryPluginInterface {

  protected $database;
  protected $logger;

  public function __construct(array $configuration, $plugin_id, $plugin_definition, Connection $database, LoggerInterface $logger) {
    parent::__construct($configuration, $plugin_id, $plugin_definition);
    $this->database = $database;
    $this->logger = $logger;
  }

  public static function create(ContainerInterface $container, array $configuration, $plugin_id, $plugin_definition) {
    return new static(
      $configuration,
      $plugin_id,
      $plugin_definition,
      $container->get('database'),
      $container->get('logger.channel.my_module')
    );
  }

  /**
   * {@inheritdoc}
   *
   * 处理队列中的单个项目.
   * @param mixed $data
   *   队列项目的数据. 通常是对象或数组.
   */
  public function processItem($data) {
    // $data 可能包含需要处理的信息，例如 node ID, user ID 等
    if (isset($data->nid) && is_numeric($data->nid)) {
      $this->logger->info('Processing queue item for node @nid.', ['@nid' => $data->nid]);
      try {
        // 在这里执行耗时或需要后台处理的操作...
        // 例如：更新节点数据、与外部 API 交互、发送邮件等
        // $node = \Drupal::entityTypeManager()->getStorage('node')->load($data->nid);
        // if ($node) { ... }
        // 模拟处理
        sleep(1); // 模拟耗时操作
        $this->logger->info('Finished processing node @nid.', ['@nid' => $data->nid]);
      }
      catch (\Exception $e) {
        $this->logger->error('Failed to process queue item for node @nid: @message', [
            '@nid' => $data->nid,
            '@message' => $e->getMessage(),
          ]);
        // 可以选择重新将任务放回队列或记录失败
        // throw new \Drupal\Core\Queue\SuspendQueueException('Processing failed, retrying later.');
      }
    } else {
        $this->logger->warning('Invalid data received in queue item: @data', ['@data' => print_r($data, TRUE)]);
    }
  }
}

3.6 钩子系统 (Hook System)​

尽管是传统机制，但在 Drupal 10+ 中仍然广泛用于许多场景，特别是与实体生命周期、表单处理、主题预处理等相关的操作。

  • 实现: 在模块的 .module 文件中定义遵循 MODULENAME_hook_name() 命名约定的函数。
  • 发现: Drupal 会自动查找并调用已启用模块中的钩子实现。
// modules/custom/my_module/my_module.module

use Drupal\Core\Entity\EntityInterface;
use Drupal\Core\Form\FormStateInterface;

/**
 * Implements hook_ENTITY_TYPE_presave().
 *
 * 例如：在节点保存前修改字段值.
 */
function my_module_node_presave(EntityInterface $node) {
  // 检查是否是 "article" 类型的节点
  if ($node->bundle() === 'article') {
    // 如果某个字段为空，设置默认值
    if ($node->hasField('field_custom_status') && $node->get('field_custom_status')->isEmpty()) {
      $node->set('field_custom_status', 'pending');
      \Drupal::logger('my_module')->info('Set default status for article @nid.', ['@nid' => $node->id() ?? 'new']);
    }
  }
}

/**
 * Implements hook_form_FORM_ID_alter().
 *
 * 特定表单修改，例如用户注册表单.
 */
function my_module_form_user_register_form_alter(&$form, FormStateInterface $form_state, $form_id) {
  // 给用户注册表单添加一个自定义字段或修改现有字段
  $form['account']['pass']['#description'] = t('Password must be at least 12 characters long.');

  // 添加自定义提交处理函数
  $form['actions']['submit']['#submit'][] = 'my_module_user_register_form_submit';
}

4. 实体与字段 API (Entity & Field API)​

这是 Drupal 内容建模的核心。

4.1 实体类型、束、实例​

  • 实体类型: 定义数据的基本类型和行为（node, user, taxonomy_term, custom_entity_type）。
  • 束: 实体类型的子类型，允许同一实体类型有不同的字段集和配置（article, page 是 node 的束）。
  • 实例: 具体的实体对象（一篇特定的文章，一个用户）。

4.2 字段类型、存储、实例​

  • 字段类型: 定义数据的原子类型（string, text_long, entity_reference, image, boolean）。由 Field Type 插件实现。
  • 字段存储: 定义字段的数据库存储设置，不依赖于特定的束。一个存储可以被多个束使用。
  • 字段实例: 将字段存储附加到特定的束，并配置该束下的字段行为（标签、是否必须、Widget、Formatter、默认值等）。

4.3 编程交互​

使用 EntityTypeManager 服务 (@entity_type.manager) 来获取特定实体类型的存储处理器 (Storage handler)，然后用存储处理器进行 CRUD 操作。

<?php
use Drupal\node\Entity\Node;
use Drupal\user\Entity\User;
use Drupal\taxonomy\Entity\Term;

$entity_type_manager = \Drupal::service('entity_type.manager');

// --- 加载 Load ---
$node_storage = $entity_type_manager->getStorage('node');
$node = $node_storage->load(1); // Load Node ID 1
if ($node) {
    $title = $node->getTitle();
    $body = $node->get('body')->value; // Access field value directly
    // 访问实体引用字段 (假设 field_tags 是一个指向分类术语的字段)
    $tags = $node->get('field_tags')->referencedEntities(); // Get referenced Term objects
    foreach ($tags as $tag) {
        if ($tag instanceof Term) {
            echo 'Tag: ' . $tag->getName() . '<br>';
        }
    }
}

// --- 创建 Create ---
$new_article = Node::create([
    'type'        => 'article', // Bundle
    'title'       => 'New Article via Code',
    'uid'         => 1, // Author user ID
    'status'      => Node::PUBLISHED, // Use constants for status
    'body'        => [
        'value' => 'This is the article body content.',
        'format' => 'basic_html',
    ],
    'field_tags'  => [ // Assigning entity reference values (by target_id)
        ['target_id' => 1], // Assuming Term ID 1 exists
        ['target_id' => 2], // Assuming Term ID 2 exists
    ],
    // Add other fields as needed...
]);

// --- 保存 Save ---
$new_article->save();
$new_nid = $new_article->id();
\Drupal::messenger()->addStatus("New article created with NID: $new_nid");

// --- 更新 Update ---
$node_to_update = $node_storage->load($new_nid);
if ($node_to_update) {
    $node_to_update->setTitle('Updated Article Title');
    $node_to_update->set('status', Node::NOT_PUBLISHED); // Unpublish
    // Update entity reference - setting new values will replace old ones
    $node_to_update->set('field_tags', [['target_id' => 3]]);
    $node_to_update->save();

5. 配置管理 (Configuration Management)​

确保站点配置（非内容）可以在不同环境（开发、测试、生产）之间可靠地同步。

  • 工作流:
    1. 在开发环境修改配置 (通过 UI 或 Drush)。
    2. 导出配置到 YAML 文件: drush config:export (drush cex)
    3. 将 YAML 文件添加到版本控制 (Git)。
    4. 在目标环境下拉代码。
    5. 导入配置: drush config:import (drush cim)
  • 存储:
    • 活动存储 (Active): 数据库，驱动当前站点。
    • 同步存储 (Sync): 文件系统 (config/sync 目录默认)，用于导入/导出。
  • 配置实体 (Config Entities): 许多配置项本身也是实体（如内容类型、视图、用户角色），可以通过 EntityTypeManager 操作，但通常推荐使用配置管理流程。
  • 简单配置 (Simple Config): 单个 YAML 文件存储一组相关的设置（如 system.site.yml）。

7. 表单 API (Forms API - FAPI)​

用于构建、处理和验证 HTML 表单。

  • 表单类: 实现 FormInterface，通常继承自 FormBase 或 ConfigFormBase (用于配置表单)。
  • 核心方法:
    • getFormId(): 返回表单的唯一 ID。
    • buildForm(): 构建表单的渲染数组 (定义字段、按钮等)。
    • validateForm(): 验证提交的数据。使用 $form_state->setErrorByName() 设置错误。
    • submitForm(): 处理验证通过后的数据（保存数据、重定向等）。
  • 渲染数组 (#type): FAPI 使用渲染数组定义表单元素，如 textfield, textarea, checkbox, select, submit 等。
// modules/custom/my_module/src/Form/MyCustomForm.php
namespace Drupal\my_module\Form;

use Drupal\Core\Form\FormBase;
use Drupal\Core\Form\FormStateInterface;
use Symfony\Component\DependencyInjection\ContainerInterface; // For DI
use Drupal\Core\Database\Connection; // Example DI

class MyCustomForm extends FormBase {

  protected $database;

  // Dependency Injection is preferred
  public function __construct(Connection $database) {
    $this->database = $database;
  }

  public static function create(ContainerInterface $container) {
    return new static(
      $container->get('database')
    );
  }

  /**
   * {@inheritdoc}
   */
  public function getFormId() {
    return 'my_module_custom_form'; // Unique form ID
  }

  /**
   * {@inheritdoc}
   */
  public function buildForm(array $form, FormStateInterface $form_state) {
    $form['name'] = [
      '#type' => 'textfield',
      '#title' => $this->t('Your Name'), // Use t() for translatable strings
      '#required' => TRUE,
      '#description' => $this->t('Please enter your full name.'),
    ];

    $form['email'] = [
      '#type' => 'email',
      '#title' => $this->t('Your Email'),
      '#required' => TRUE,
    ];

    $form['feedback_type'] = [
      '#type' => 'select',
      '#title' => $this->t('Feedback Type'),
      '#options' => [
        'bug' => $this->t('Bug Report'),
        'feature' => $this->t('Feature Request'),
        'comment' => $this->t('General Comment'),
      ],
      '#empty_option' => $this->t('- Select -'),
    ];

    $form['message'] = [
      '#type' => 'textarea',
      '#title' => $this->t('Message'),
      '#required' => TRUE,
    ];

    $form['actions']['submit'] = [
      '#type' => 'submit',
      '#value' => $this->t('Send Feedback'),
      '#button_type' => 'primary',
    ];

    return $form;
  }

  /**
   * {@inheritdoc}
   */
  public function validateForm(array &$form, FormStateInterface $form_state) {
    parent::validateForm($form, $form_state); // Good practice to call parent

    $name = $form_state->getValue('name');
    $email = $form_state->getValue('email');
    $message = $form_state->getValue('message');

    if (strlen($name) < 3) {
      $form_state->setErrorByName('name', $this->t('Name must be at least 3 characters long.'));
    }

    if (!empty($email) && !\Drupal::service('email.validator')->isValid($email)) {
       $form_state->setErrorByName('email', $this->t('Please enter a valid email address.'));
    }

    if (str_word_count($message) < 5) {
        $form_state->setErrorByName('message', $this->t('Message must contain at least 5 words.'));
    }
  }

  /**
   * {@inheritdoc}
   */
  public function submitForm(array &$form, FormStateInterface $form_state) {
    // Form validation passed, process the submitted values.
    $name = $form_state->getValue('name');
    $email = $form_state->getValue('email');
    $feedback_type = $form_state->getValue('feedback_type');
    $message = $form_state->getValue('message');

    // Example: Log the submission (using injected database service)
    try {
      $this->database->insert('my_feedback_log')
        ->fields([
          'name' => $name,
          'email' => $email,
          'type' => $feedback_type,
          'message' => $message,
          'timestamp' => \Drupal::time()->getRequestTime(),
        ])
        ->execute();

      $this->messenger()->addStatus($this->t('Thank you for your feedback, @name!', ['@name' => $name]));

      // Optionally redirect after submission
      // $form_state->setRedirect('some.route.name');

    } catch (\Exception $e) {
       $this->messenger()->addError($this->t('An error occurred while saving your feedback. Please try again.'));
       $this->getLogger('my_module')->error('Failed to save feedback: @message', ['@message' => $e->getMessage()]);
    }

    // Values are available via $form_state->getValue('field_name');
    // Perform actions like saving data, sending emails, etc.
  }

}

9. 缓存系统 (Caching)​

Drupal 的性能严重依赖其多层缓存系统。后端开发需要理解如何与缓存交互，确保内容动态更新且性能良好。

  • 缓存层级: Page Cache (匿名用户完整 HTML), Dynamic Page Cache (认证用户部分页面, 依赖占位符), Render Cache (渲染数组片段), Data Cache (实体、配置等), Twig Cache。
  • 缓存元数据 (Cacheability Metadata):
    • 缓存标签 (Tags): 用于失效缓存。当与标签关联的数据（如 node:5, user:1, config:system.site）发生变化时，所有包含该标签的缓存项都会被清除。
    • 缓存上下文 (Contexts): 用于区分缓存变体。告诉 Drupal 缓存项依赖于哪些上下文信息（如 user, url.query_args, languages）。不同的上下文值会产生不同的缓存项。
    • 缓存最大期限 (Max-age): 缓存项的最长有效时间 (0 表示不缓存, -1 或 Cache::PERMANENT 表示永久直到失效)。
  • 添加元数据: 通常在渲染数组的 #cache 键中设置。实体和许多 Drupal API 调用会自动添加必要的元数据。
  • 缓存失效: 通过修改实体、配置或手动清除标签 (\Drupal\Core\Cache\Cache::invalidateTags(['tag1', 'tag2'])) 来触发。
  • 占位符 (Placeholders) & Auto-placeholdering: 用于 Dynamic Page Cache，将页面中高度动态的部分（如用户名称、购物车）替换为占位符，主体页面可被缓存，占位符在后续请求或 BigPipe 技术中填充。

10. 安全性 (Security)​

后端开发是安全的关键环节。

  • 输入过滤/验证:
    • 绝不信任任何来自用户或外部的数据。
    • 使用 Forms API 的验证机制。
    • 使用 PHP 的 filter_var() 函数。
    • 使用 Drupal 的约束 (Constraints) API 进行实体验证。
    • 对数据库查询使用参数绑定 (见数据库 API 和实体查询)。
  • 输出转义:
    • 首选: 让 Twig 自动转义或使用安全的渲染数组元素 (#markup 通常不安全，除非内容已知安全；#plain_text 安全)。
    • 在需要手动转义的地方使用 Drupal\Component\Utility\Html::escape()。
    • 使用 check_plain() (旧函数，等同于 Html::escape())。
  • 访问控制:
    • 使用权限系统 (*.permissions.yml 定义权限，路由/钩子/代码中检查权限)。
    • 使用实体访问钩子 (hook_entity_access, hook_ENTITY_TYPE_access) 控制实体级访问。
    • 使用字段访问钩子 (hook_entity_field_access) 控制字段级访问。
  • 跨站脚本 (XSS): 通过正确的输出转义来防止。
  • SQL 注入: 通过使用 Drupal 数据库 API 的参数绑定和实体查询 API 来防止。
  • 跨站请求伪造 (CSRF): Forms API 自动包含 CSRF 令牌保护。对于非表单操作（如链接），需要手动生成和验证令牌 (\Drupal::csrfToken()->get(), \Drupal::csrfToken()->validate())。
  • 配置安全: 不要将敏感信息（API 密钥、密码）直接存储在版本控制的配置 YAML 文件中。使用 settings.php、环境变量或 Key 模块等。

11. APIs (Headless/Decoupled Drupal)​

Drupal 提供了强大的 API 优先能力，允许将其作为后端为前端应用（React, Vue, Angular 等）或其他系统提供数据。

  • 核心模块:
    • JSON:API: 提供符合 JSON:API 规范的、功能完整的 API，覆盖所有实体类型和字段。通常是推荐的开箱即用方案。自动处理 CRUD、关系、过滤、排序、分页。
    • RESTful Web Services (rest): 提供更底层的框架，可以自定义 REST 资源插件来创建更定制化的 API 端点。需要更多配置。
    • Serialization: 提供将实体等数据序列化为 JSON, XML 等格式的基础。
  • 配置: 通过 UI 或配置 YAML (如 rest.resource.*.yml) 启用和配置资源、格式、认证方法。
  • 认证: 通常使用 OAuth 2.0 (需要额外模块如 simple_oauth) 或基本认证 (不推荐用于生产) 或 Cookie 认证 (用于同域 JS 应用)。

  • @database: 数据库连接。
  • @config.factory: 读取和写入配置。
  • @logger.channel.my_module: (或特定通道) 日志记录。
  • @string_translation: 提供 t() 函数等翻译功能 (通过 StringTranslationTrait)。
  • @renderer: 将渲染数组渲染成 HTML。
  • @current_user: 获取当前登录用户对象。
  • @messenger: 向用户显示状态消息。
  • @redirect.response: 创建重定向响应。
  • @queue: 获取队列处理器。
  • @module_handler: 检查模块是否启用、调用钩子等。
  • @csrf_token: CSRF 令牌生成与验证。
  • @request_stack: 获取当前请求对象。
  • @cache_tags.invalidator: 手动失效缓存标签。
