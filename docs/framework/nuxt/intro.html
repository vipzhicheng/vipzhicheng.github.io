Nuxt.js 核心知识点

Nuxt.js 是一个基于 Vue.js 的开源框架，用于构建现代化的 Web 应用。它简化了通用 (Universal/SSR)、静态生成 (SSG) 或单页面应用 (SPA) 的开发流程，提供了许多开箱即用的功能和约定。

1. 项目结构与约定 (Directory Structure & Conventions)​

说明​

Nuxt 采用基于约定的目录结构，许多核心功能通过特定目录下的文件自动启用和配置。

  • .nuxt/: 开发过程中生成的目录，包含编译后的应用和类型定义。不应手动修改或提交到版本控制。
  • app.vue: 应用的主入口组件，类似于 Vue 应用的 App.vue，用于定义全局布局或包裹所有页面。
  • assets/: 存放需要通过构建工具（如 Vite 或 Webpack）处理的资源（如 CSS, Sass, Images, Fonts）。引用时使用相对路径或别名 (~/assets/...)。
  • components/: 存放 Vue 组件。Nuxt 3 会自动导入此目录下的组件，无需手动 import。支持子目录。
  • composables/: 存放 Vue 组合式函数 (Composition API)。Nuxt 3 会自动导入此目录下的函数。
  • content/: (需要 @nuxt/content 模块) 存放基于 Markdown/YAML/CSV/JSON 等格式的内容文件，用于构建内容驱动的网站。
  • layouts/: 定义应用的布局模板。layouts/default.vue 是默认布局。页面可以通过 definePageMeta 指定使用哪个布局。
  • middleware/: 定义路由中间件，可以在页面导航发生之前或之后执行代码（如权限验证、数据预取）。
  • modules/: 存放本地 Nuxt 模块，用于扩展 Nuxt 的核心功能。
  • node_modules/: 项目依赖。
  • pages/: 定义应用的视图和路由。Nuxt 会根据此目录的文件结构自动生成 Vue Router 配置。
  • plugins/: 存放需要在 Vue 应用实例化时运行的插件（如集成第三方库、注入全局属性/方法）。
  • public/: 存放不需要构建处理、直接从服务器根路径 (/) 提供的静态资源（如 robots.txt, favicon.ico, 图片）。
  • server/: 定义服务器端的 API 路由、中间件和插件 (使用 Nitro 引擎)。
    • server/api/**: 创建 API 端点。
    • server/routes/**: 创建具有自定义路由参数的服务器路由。
    • server/middleware/**: 创建服务器请求的中间件。
    • server/plugins/**: Nitro 服务器引擎插件。
    • server/utils/**: 服务器工具函数。
  • utils/: 存放工具函数。Nuxt 3 会自动导入此目录下的函数。
  • nuxt.config.ts: Nuxt 的核心配置文件。
  • package.json: 项目依赖和脚本。
  • tsconfig.json: TypeScript 配置文件，Nuxt 自动生成和维护。

2. 路由系统 (Routing - pages/ directory)​

说明​

Nuxt 基于 pages/ 目录结构自动生成 Vue Router 配置。

  • 基础路由: pages/user.vue -> /user
  • 首页: pages/index.vue -> /
  • 嵌套路由: 创建一个与 .vue 文件同名的目录来包含子视图。需要 <NuxtPage /> (相当于 <RouterView />) 组件来显示子页面。
    • pages/parent.vue
    • pages/parent/child.vue -> /parent/child
  • 动态路由: 使用方括号 []。
    • pages/users-[group]/[id].vue -> /users-:group/:id
  • 捕获所有路由 (Catch-all): 使用带有三个点的方括号 [...]。
    • pages/categories/[...slug].vue -> /categories/*
  • <NuxtLink>: 用于内部导航的组件，类似 Vue Router 的 <RouterLink>。
  • <NuxtPage>: 用于显示当前匹配路由的页面组件，类似 <RouterView>。
  • 编程式导航: 使用 navigateTo() 工具函数。
  • 路由元数据 (definePageMeta): 在 <script setup> 中使用 definePageMeta 宏来设置页面特定的配置，如布局、中间件、别名等。

示例代码​

<!-- pages/index.vue -->
<template>
  <div>
    <h1>Welcome to the Homepage</h1>
    <NuxtLink to="/about">About Page</NuxtLink> <br />
    <NuxtLink to="/products/123">Product 123</NuxtLink> <br />
    <button @click="goToAbout">Go to About Programmatically</button>
  </div>
</template>

<script setup>
function goToAbout() {
  navigateTo("/about");
}
</script>

<!-- pages/about.vue -->
<template>
  <div>
    <h1>About Us</h1>
    <NuxtLink to="/">Go Home</NuxtLink>
    <p>This page uses the 'custom' layout.</p>
  </div>
</template>

<script setup>
// Define page meta data
definePageMeta({
  layout: "custom", // Use layouts/custom.vue
  middleware: ["auth"], // Apply middleware/auth.ts
});
</script>

<!-- pages/products/[id].vue -->
<template>
  <div>
    <h1>Product Detail</h1>
    <p>Product ID: {{ $route.params.id }}</p>
    <!-- Access route params (alternative in script setup: useRoute()) -->
    <p>(Composable access) Product ID: {{ route.params.id }}</p>
  </div>
</template>

<script setup>
import { useRoute } from "vue-router"; // Or directly from '#imports' in Nuxt
const route = useRoute();
console.log("Product ID:", route.params.id);

// You can also validate params

3. 渲染模式 (Rendering Modes)​

说明​

Nuxt 支持多种渲染模式，可以在 nuxt.config.ts 中配置或根据构建/启动命令选择。

  • 通用渲染 (Universal / SSR): 默认模式。页面在服务器上渲染首屏 HTML，然后发送到客户端进行 "激活" (Hydration)。利于 SEO 和首屏加载速度。npm run dev, npm run build + npm run start (或部署 Node server)。
  • 客户端渲染 (SPA): 仅在客户端渲染。类似于传统的 Vue SPA。nuxt.config.ts 中设置 ssr: false。npm run build + 静态托管。
  • 静态站点生成 (SSG): 在构建时预渲染所有页面为 HTML 文件。性能极佳，易于部署。npm run generate。
  • 混合渲染 (Hybrid): 可以为特定路由配置不同的渲染方式（例如，大部分页面 SSG，某些动态页面 SSR）。通过 routeRules 在 nuxt.config.ts 中配置。
  • 边缘渲染 (Edge Side Rendering - ESR): (需要支持的环境如 Vercel, Netlify) 在 CDN 边缘节点进行 SSR，兼顾速度和动态性。

示例代码 (nuxt.config.ts)​

// nuxt.config.ts
export default defineNuxtConfig({
  // Option 1: Global SSR toggle (false for SPA)
  // ssr: true, // Default is true

  // Option 2: Route Rules for Hybrid Rendering
  routeRules: {
    // Render specific page in SPA mode
    "/admin/**": { ssr: false },
    // Render specific page statically (SSG - prerendered at build time)
    "/static-page": { prerender: true },
    // Render specific page with ISR (Incremental Static Regeneration)
    "/products/**": { isr: 60 }, // Revalidate every 60 seconds
    // Redirect
    "/old-page": { redirect: "/new-page" },
    // Add headers
    "/secure/**": { headers: { "X-Custom-Header": "value" } },
    // Use swr (stale-while-revalidate) caching on server routes
    "/api/data": { swr: 3600 },
  },

  // Other config...
});

4. 数据获取 (Data Fetching)​

说明​

Nuxt 3 提供了强大的组合式函数 (composables) 来进行同构 (isomorphic) 数据获取，即同一套代码可以在服务器端和客户端运行。

  • useFetch: 最常用的 composable。它会自动处理服务器端获取、客户端激活时的数据传递、客户端导航时的获取、缓存、pending 状态、错误处理等。
  • useAsyncData: 提供了对异步操作更底层的控制。接收一个唯一的 key 和一个异步函数。useFetch 内部就是基于 useAsyncData 实现的。适用于需要更复杂逻辑或非 fetch API 的场景。
  • $fetch: Nuxt 提供的全局 fetch 实例，基于 ofetch 库。它在服务器端可以直接调用内部 API 路由，在客户端则发送正常 HTTP 请求。支持自动解析 JSON、错误处理等。useFetch 内部使用 $fetch。
  • 服务器端获取: 这些 composables 在 SSR 期间会在服务器执行，数据会嵌入到 HTML payload 中传递给客户端。
  • 客户端获取: 在客户端导航时，它们会发起请求获取数据。

示例代码​

<!-- pages/posts.vue -->
<template>
  <div>
    <h1>Blog Posts</h1>
    <div v-if="pending">Loading posts...</div>
    <div v-else-if="error">Error: {{ error.message }}</div>
    <ul v-else>
      <li v-for="post in posts" :key="post.id">
        {{ post.title }}
      </li>
    </ul>
    <button @click="refreshPosts" :disabled="pending">Refresh</button>

    <h2>Single Post (useAsyncData)</h2>
    <div v-if="singlePostPending">Loading single post...</div>
    <div v-else-if="singlePostError">Error: {{ singlePostError.message }}</div>
    <p v-else>{{ singlePost?.title }}</p>
  </div>
</template>

<script setup>
// Option 1: useFetch (recommended for simple GET requests)
// The URL can be an API endpoint or a server route /api/...
const {
  data: posts,
  pending,
  error,
  refresh: refreshPosts,
} = await useFetch("https://jsonplaceholder.typicode.com/posts?_limit=10", {
  // Options:
  // lazy: true, // Don't block navigation, show loading state instead
  // server: false, // Only fetch on client side
  // pick: ['id', 'title'], // Only pick specific keys
  // key: 'posts-list' // Unique key if URL isn't static enough
});

// Option 2: useAsyncData (more control)
const postId = ref(1);
const {
  data: singlePost,
  pending: singlePostPending,
  error: singlePostError,
} = await useAsyncData(
  `post-${postId.value}`, // Unique key, often includes dynamic parts
  () => $fetch(`https://jsonplaceholder.typicode.com/posts/${postId.value}`), // Async function using $fetch
  {
    watch: [postId], // Re-run async function when postId changes
  }
);

// Handle potential errors (e.g., show error page)
if (error.value) {
  // showError({ statusCode: 500, statusMessage: 'Failed to fetch posts' })
  console.error("Failed to fetch posts:", error.value);
}
if (singlePostError.value) {
  console.error("Failed to fetch single post:", singlePostError.value);
}
</script>

5. 组件 (components/)​

说明​

Nuxt 3 极大地简化了组件的使用。

  • 自动导入: components/ 目录下的所有 .vue 文件（及其子目录中的文件）都会被自动按需导入。你可以在模板或 <script setup> 中直接使用它们，无需 import 语句。
  • 命名:
    • components/MyButton.vue -> <MyButton />
    • components/User/Profile.vue -> <UserProfile /> (目录名 + 文件名)
  • 动态组件: 可以使用 Vue 的 <component :is="componentName">。
  • ClientOnly 组件: Nuxt 提供 <ClientOnly> 组件来包裹那些只能在客户端渲染的组件或部分。

示例代码​

<!-- components/TheHeader.vue -->
<template>
  <header style="background-color: #eee; padding: 10px;">
    Site Header - <NuxtLink to="/">Home</NuxtLink>
  </header>
</template>

<!-- components/App/Button.vue -->
<template>
  <button style="background-color: blue; color: white; padding: 5px 10px;">
    <slot />
    <!-- Default slot for button text -->
  </button>
</template>

<!-- pages/index.vue -->
<template>
  <div>
    <!-- TheHeader and AppButton are auto-imported -->
    <TheHeader />
    <h1>Homepage</h1>
    <AppButton @click="handleClick">Click Me</AppButton>

    <ClientOnly>
      <!-- This component/part will only render on the client -->
      <SomeClientSideLibraryComponent />
      <template #fallback>
        <!-- Optional: loading indicator shown on server/initial load -->
        <p>Loading map...</p>
      </template>
    </ClientOnly>
  </div>
</template>

<script setup>
function handleClick() {
  console.log("AppButton clicked");
}

// If you NEEDED to reference a component instance in script (less common now):
// const myButtonRef = ref(null); // Attach ref="myButtonRef" to <AppButton>
</script>

6. 布局 (layouts/)​

说明​

布局用于提供跨多个页面的通用 UI 结构（如页眉、页脚、侧边栏）。

  • layouts/default.vue: 如果存在，则作为所有未指定布局的页面的默认布局。
  • 自定义布局: 在 layouts/ 下创建其他 .vue 文件，如 layouts/custom.vue。
  • <slot />: 布局文件必须包含一个 <slot /> 组件，用于渲染当前页面的内容。
  • 应用布局: 在页面组件的 <script setup> 中使用 definePageMeta({ layout: 'layout-name' }) 来指定布局。'default' 可省略。也可以动态设置为 false 来禁用布局。

示例代码​

<!-- layouts/default.vue -->
<template>
  <div>
    <TheHeader />
    <!-- Auto-imported component -->
    <main style="padding: 20px;">
      <!-- Page content will be rendered here -->
      <slot />
    </main>
    <footer
      style="margin-top: 20px; border-top: 1px solid #ccc; padding: 10px;"
    >
      Default Layout Footer
    </footer>
  </div>
</template>

<!-- layouts/custom.vue -->
<template>
  <div style="background-color: lightblue;">
    <header style="padding: 10px; background-color: darkblue; color: white;">
      Custom Layout Header
    </header>
    <main style="padding: 20px;">
      <slot />
      <!-- Page content -->
    </main>
  </div>
</template>

<!-- pages/about.vue -->
<script setup>
definePageMeta({
  layout: "custom", // Use layouts/custom.vue for this page
});
</script>
<template>
  <h1>About page using custom layout</h1>
</template>

<!-- pages/index.vue -->
<!-- No definePageMeta needed, uses layouts/default.vue -->
<template>
  <h1>Homepage using default layout</h1>
</template>

7. 状态管理 (State Management)​

说明​

Nuxt 3 提供了多种管理共享状态的方式。

  • useState Composable: Nuxt 提供的内置响应式、SSR 友好的 Composable，用于在组件之间共享简单的状态。它创建的状态在服务器端渲染时会传递给客户端。需要一个唯一的 key。
  • Pinia: 官方推荐的 Vue 状态管理库。Nuxt 提供了 @pinia/nuxt 模块，可以轻松集成，并支持 SSR。
  • Provide/Inject: Vue 的标准依赖注入机制也可用于传递状态，但不直接支持 SSR 状态传递。

示例代码​

useState​

// composables/useMyState.ts
// Simple shared state across components, SSR-friendly
export const useCounter = () => useState<number>('counter', () => 0);
export const useUser = () => useState<User | null>('user', () => null); // Example with type

// components/CounterDisplay.vue
<template>
  <p>Counter (useState): {{ counter }}</p>
</template>
<script setup>
const counter = useCounter();
</script>

// components/CounterButton.vue
<template>
  <button @click="counter++">Increment (useState)</button>
</template>
<script setup>
const counter = useCounter();
</script>

Pinia​

  1. 安装: npm install pinia @pinia/nuxt

  2. 添加模块到 nuxt.config.ts:

    // nuxt.config.ts
    export default defineNuxtConfig({
      modules: ["@pinia/nuxt"],
    });

  3. 创建 Store:

    // stores/cart.ts
    import { defineStore } from "pinia";

    export const useCartStore = defineStore("cart", {
      state: () => ({
        items: [] as string[],
        count: 0,
      }),
      actions: {
        addItem(item: string) {
          this.items.push(item);
          this.count++;
        },
        removeItem(itemToRemove: string) {
          this.items = this.items.filter((item) => item !== itemToRemove);
          this.count = this.items.length; // Recalculate count
        },
      },
      getters: {
        // Example getter
        // isEmpty: (state) => state.count === 0,
      },
    });

  4. 在组件中使用:

    // components/AddToCart.vue
    <template>
      <button @click="addToCart">Add Item to Cart (Pinia)</button>
    </template>
    <script setup>
    import { useCartStore } from "~/stores/cart"; // Path relative to root
    const cartStore = useCartStore();
    const itemName = "Product " + Math.random().toString(36).substring(7);

    function addToCart() {
      cartStore.addItem(itemName);
    }
    </script>

    // components/CartDisplay.vue
    <template>
      <div>
        <h3>Cart (Pinia)</h3>
        <p>Items: {{ cartStore.count }}</p>
        <ul>
          <li v-for="(item, index) in cartStore.items" :key="index">
            {{ item }}
          </li>
        </ul>
      </div>
    </template>
    <script setup>
    import { useCartStore } from "~/stores/cart";
    const cartStore = useCartStore();
    </script>

8. 插件 (plugins/)​

说明​

插件允许你在 Vue 应用初始化时运行代码。常用于：

  • 注册全局组件或指令。
  • 添加 Vue 原型方法或全局属性。
  • 集成第三方库（如 UI 库、分析工具）。
  • 运行应用启动逻辑。
  • 文件名后缀 .client 或 .server 可指定插件仅在客户端或服务器端运行。

9. 中间件 (middleware/)​

说明​

路由中间件允许你在导航到某个路由之前执行逻辑。可用于权限检查、重定向、加载布局所需数据等。

  • 命名: 文件名即中间件名 (e.g., middleware/auth.ts)。
  • 全局中间件: 文件名添加 .global 后缀 (e.g., middleware/logger.global.ts)，会对每次路由变化都执行。
  • 定义: 导出一个 defineNuxtRouteMiddleware 函数。
  • 应用:
    • 在页面中使用 definePageMeta({ middleware: ['middleware-name'] })。
    • 在 nuxt.config.ts 的 router.options.middleware 中全局添加。
    • 在布局中设置 defineOptions({ middleware: '...' }) (不推荐)。
  • 函数签名: (to, from) => {}，可以访问目标路由 to 和来源路由 from。
  • 导航控制: 可以返回 navigateTo('/login') 进行重定向，或不返回值/返回 true 以允许导航，或返回 false / abortNavigation() 中止导航。

示例代码​

// middleware/auth.ts
export default defineNuxtRouteMiddleware((to, from) => {
  const { $auth } = useNuxtApp(); // Assuming an auth status helper/plugin exists

  console.log(`Auth middleware running for route: ${to.path}`);

  // Example: Redirect to login if trying to access /admin and not logged in
  const isLoggedIn = !!useUser().value; // Example using useState for user state

  if (to.path.startsWith("/admin") && !isLoggedIn) {
    console.log("User not logged in, redirecting to /login");
    return navigateTo("/login?redirect=" + to.fullPath); // Redirect to login page
  }

  // Allow navigation otherwise
  // return true; // or just return nothing
});

// middleware/logger.global.ts (Runs on every route change)
export default defineNuxtRouteMiddleware((to, from) => {
  console.log(
    `[Global Middleware] Navigating from ${from.fullPath} to ${to.fullPath}`
  );
});

// Apply 'auth' middleware to a page
// pages/admin/index.vue
// <script setup>
// definePageMeta({
//   middleware: 'auth' // or ['auth']
// });
// </script>

10. 服务器引擎 (Nitro) & API 路由 (server/)​

说明​

Nuxt 3 使用 Nitro 作为其服务器引擎。Nitro 提供了强大的后端能力，包括：

  • API 路由 (server/api/): 在此目录下创建文件，可以自动创建 API 端点。文件名即路由路径，支持 HTTP 方法 (通过文件后缀 .get.ts, .post.ts 或在文件中判断 event.node.req.method)。
  • 服务器路由 (server/routes/): 创建更复杂的服务器路由，支持自定义参数。
  • 服务器中间件 (server/middleware/): 在处理 API 或服务器路由请求之前执行的逻辑（如日志、认证、请求预处理）。会应用于所有服务器请求。
  • 服务器插件 (server/plugins/): 在 Nitro 服务器启动时运行，用于设置数据库连接、初始化服务等。
  • 工具函数 (server/utils/): 存放仅在服务器端使用的工具函数。
  • 上下文 (event): 处理函数接收一个 event 对象，包含请求 (event.node.req) 和响应 (event.node.res) 信息，以及 Nitro 提供的辅助函数 (readBody, getQuery, sendRedirect 等)。

示例代码​

// server/api/hello.ts (Handles all methods by default)
// Responds to GET /api/hello?name=Nuxt
import { H3Event } from "h3"; // Nitro uses H3 for routing/event handling

export default defineEventHandler((event: H3Event) => {
  const query = getQuery(event); // Helper to get query parameters
  const name = query.name || "World";

  console.log(
    `[Server API] /api/hello called. Method: ${event.node.req.method}`
  );

  if (event.node.req.method === "POST") {
    // const body = await readBody(event); // Helper to read request body
    // Handle POST logic...
    return { message: `Hello ${name}! (POST received)` };
  }

  return { message: `Hello ${name}! (GET request)` };
});

// server/api/items.get.ts (Handles only GET requests to /api/items)
let itemsDb = ["Apple", "Banana"]; // Dummy data store
export default defineEventHandler(() => {
  console.log("[Server API] GET /api/items");
  return { items: itemsDb };
});

// server/api/items.post.ts (Handles only POST requests to /api/items)
export default defineEventHandler(async (event) => {
  try {
    const body = await readBody(event);
    if (body && body.item) {
      itemsDb.push(body.item);
      console.log(`[Server API] POST /api/items - Added: ${body.item}`);
      return { success: true, item: body.item };
    } else {
      // Set response status code
      event.node.res.statusCode = 400;
      return { success: false, message: "Item is required in body" };
    }
  } catch (e) {
    event.node.res.statusCode = 400;
    return { success: false, message: "Invalid request body" };
  }
});

// server/middleware/logger.ts (Nitro server middleware)
export default defineEventHandler((event) => {
  const startTime = Date.now();
  console.log(
    `[Server Middleware] New request: ${event.node.req.method} ${event.node.req.url}`
  );

  // Modify response after handler execution (example)
  event.node.res.on("finish", () => {
    const duration = Date.now() - startTime;
    console.log(
      `[Server Middleware] Request finished: ${event.node.res.statusCode} in ${duration}ms`
    );
  });
});

11. 资源处理 (assets/ vs public/)​

说明​

  • assets/: 用于存放需要通过构建流程处理的源文件。例如，Sass 文件会被编译成 CSS，图片会被优化，字体会被处理。引用时使用相对路径或 ~/assets/ 别名，构建后路径会包含哈希值以利于缓存。
  • public/: 用于存放必须保持原始名称且不需要处理的静态文件。文件会被直接复制到输出目录的根路径。适合放 robots.txt, favicon.ico, 不可变图片等。引用时直接使用绝对路径 / (相对于根目录)。

示例代码​

<template>
  <div>
    <!-- Image from assets (processed by build tools) -->
    <img src="~/assets/images/logo.png" alt="Processed Logo" />
    <div class="my-styled-div">Styled with assets CSS</div>

    <!-- Image from public (served directly) -->
    <img src="/brand-logo.svg" alt="Public Logo" />

    <!-- Link to a file in public -->
    <a href="/documents/terms.pdf" target="_blank">Terms (PDF)</a>
  </div>
</template>

<style scoped>
/* Example importing from assets */
@import "~/assets/css/variables.css";

.my-styled-div {
  color: var(--primary-color); /* Using variable from imported CSS */
  /* Background image from assets */
  background-image: url("~/assets/images/background.jpg");
}
</style>

<!-- Assumes: -->
<!-- assets/images/logo.png -->
<!-- assets/images/background.jpg -->
<!-- assets/css/variables.css -->
<!-- public/brand-logo.svg -->
<!-- public/documents/terms.pdf -->

12. 配置 (nuxt.config.ts)​

说明​

Nuxt 的主要配置文件，用于定制框架行为、添加模块、设置元数据、配置构建选项等。使用 TypeScript (.ts) 文件可以获得类型提示。

  • defineNuxtConfig: 辅助函数，提供类型安全和自动补全。
  • 常用配置项:
    • ssr: 启用/禁用服务器端渲染。
    • devtools: 启用/禁用 Nuxt DevTools。
    • modules: 注册 Nuxt 模块。
    • css: 全局注入 CSS 文件。
    • vite / webpack: 配置底层构建工具。
    • runtimeConfig: 定义可在运行时访问的环境变量（区分公共和私有）。
    • app: 配置应用元数据（head, pageTransition, layoutTransition）。
    • routeRules: 定义路由级别的渲染和缓存规则。
    • nitro: 配置 Nitro 服务器引擎。
    • alias: 定义路径别名。

示例代码 (nuxt.config.ts)​

import { defineNuxtConfig } from "nuxt/config";

export default defineNuxtConfig({
  devtools: { enabled: true },

  // Enable SSR (default)
  ssr: true,

  // Global CSS
  css: [
    "~/assets/css/main.css", // Path relative to source directory (srcDir)
  ],

  // Modules
  modules: [
    "@pinia/nuxt", // Example: Pinia state management
    // '@nuxtjs/tailwindcss', // Example: Tailwind CSS module
  ],

  // Runtime Config (Environment Variables)
  runtimeConfig: {
    // Private keys, only available on server-side
    apiSecret: process.env.NUXT_API_SECRET || "default_secret", // Read from .env
    // Public keys that are exposed to the client-side
    public: {
      apiBase: process.env.NUXT_PUBLIC_API_BASE || "/api",
    },
  },

  // App Metadata (Head, Transitions)
  app: {
    head: {
      charset: "utf-8",
      viewport: "width=device-width, initial-scale=1",
      title: "My Awesome Nuxt App",
      meta: [{ name: "description", content: "Site description" }],
      link: [{ rel: "icon", type: "image/x-icon", href: "/favicon.ico" }],
    },
    pageTransition: { name: "page", mode: "out-in" }, // Example CSS transition
    layoutTransition: { name: "layout", mode: "out-in" },
  },

  // Vite specific config (if needed)
  // vite: {
  //   css: {
  //     preprocessorOptions: {
  //       scss: {
  //         additionalData: '@use "@/assets/_colors.scss" as *;'
  //       }
  //     }
  //   }
  // },

  // Nitro server config (if needed)
  // nitro: {
  //   preset: 'vercel', // Example for Vercel deployment
  // }
});

13. Nuxt 模块 (Modules)​

说明​

模块是 Nuxt 的核心扩展机制。它们可以封装可重用的功能，如集成 UI 库、添加分析、优化图片、集成 CMS 等。

  • 安装: 通过 npm/yarn 安装社区或官方模块。
  • 注册: 在 nuxt.config.ts 的 modules 数组中添加模块名称或路径。
  • 配置: 许多模块允许通过 nuxt.config.ts 中的同名 key 或在 modules 数组中使用元组 ['module-name', { options }] 来传递配置选项。
  • 官方模块示例: @nuxt/content, @nuxt/image, @pinia/nuxt, @nuxtjs/tailwindcss.

示例代码 (nuxt.config.ts 注册模块)​

export default defineNuxtConfig({
  modules: [
    // Simple registration
    "@pinia/nuxt",
    "@nuxt/image", // Requires installation: npm install -D @nuxt/image

    // Registration with options (example for a hypothetical auth module)
    // ['@nuxtjs/auth-next', {
    //   strategies: {
    //     local: { /* ... */ }
    //   }
    // }],
  ],

  // Module specific configuration (some modules use this convention)
  // image: {
  //   provider: 'ipx', // or 'cloudinary', 'imgix', etc.
  //   screens: { /* ... */ }
  // },

  // runtimeConfig can often be used by modules too
  // runtimeConfig: {
  //   public: {
  //     content: {
  //       // Content module options accessible at runtime
  //     }
  //   }
  // }
});

14. SEO 与元数据 (useHead)​

说明​

Nuxt 提供了 useHead composable 来动态管理文档的 <head> 部分，对于 SEO 和社交分享至关重要。

  • 响应式: useHead 接受响应式数据 (refs, computed properties)。
  • SSR 支持: 在服务器端渲染期间，useHead 会收集元数据并将其注入到初始 HTML 的 <head> 中。
  • 使用位置: 可以在页面、布局或组件的 <script setup> 中使用。
  • app.head (全局): 在 nuxt.config.ts 中设置全局默认值。页面/组件中的 useHead 会覆盖或合并这些默认值。

示例代码​

<!-- pages/products/[id].vue -->
<template>
  <div>
    <h1>{{ product?.title || "Loading..." }}</h1>
    <p>{{ product?.description }}</p>
  </div>
</template>

<script setup>
const route = useRoute();
const productId = route.params.id;

// Fetch product data
const { data: product, error } = await useFetch(`/api/products/${productId}`); // Assuming API route exists

if (error.value) {
  showError({ statusCode: 404, statusMessage: "Product not found" });
}

// Set dynamic head metadata using useHead
useHead({
  title: () => `${product.value?.title || "Product"} | My Store`, // Reactive title
  meta: [
    {
      name: "description",
      content: () =>
        product.value?.description || "Check out this amazing product.",
    },
    // Open Graph tags for social sharing
    {
      property: "og:title",
      content: () => `${product.value?.title || "Product"} | My Store`,
    },
    { property: "og:description", content: () => product.value?.description },
    { property: "og:image", content: () => product.value?.thumbnail }, // Assuming product has a thumbnail URL
    {
      property: "og:url",
      content: () => `https://mystore.com/products/${productId}`,
    },
    { property: "og:type", content: "product" },
    // Twitter card tags
    // { name: 'twitter:card', content: 'summary_large_image' },
  ],
  // link: [
  //   { rel: 'canonical', href: () => `https://mystore.com/products/${productId}` }
  // ],
  // bodyAttrs: { // Example: adding class to body
  //   class: 'product-page'
  // }
});
</script>

15. 错误处理​

说明​

Nuxt 提供了处理错误的机制。

  • error.vue: 在项目根目录 (srcDir) 下创建 error.vue 文件来自定义全局错误页面。它会接收一个 error prop，包含错误信息 (statusCode, statusMessage, message, stack)。
  • showError: 一个全局辅助函数，用于在客户端或服务器端触发错误页面显示。可以传入错误对象或状态码/消息。
  • clearError: 一个全局辅助函数，用于清除当前错误并尝试重定向回正常页面（通常与 error.vue 中的“返回首页”按钮结合使用）。
  • App Router Error Component (error.js): (Nuxt 3.x experimental/future) Nuxt is aligning with Next.js's App Router concepts, which include route segment error boundaries (error.js). This is less common in stable Nuxt 3 as of writing compared to the global error.vue.

示例代码​

<!-- error.vue (in project root, alongside app.vue) -->
<template>
  <NuxtLayout name="custom">
    <!-- Optional: Use a specific layout -->
    <div style="text-align: center; padding: 50px;">
      <h1>Error {{ error.statusCode }}</h1>
      <p>
        {{
          error.statusMessage ||
          error.message ||
          "An unexpected error occurred."
        }}
      </p>
      <pre v-if="isDev && error.stack">{{ error.stack }}</pre>
      <button @click="handleErrorClear">Go back to Home</button>
    </div>
  </NuxtLayout>
</template>

<script setup>
const props = defineProps({
  error: Object, // Nuxt automatically passes the error object here
});

const isDev = process.dev;

// Use appropriate layout (optional)
// definePageMeta({
//   layout: 'error-layout' // If you have layouts/error-layout.vue
// });

useHead({
  title: `Error ${props.error.statusCode} | My Site`,
  meta: [{ name: "description", content: "Something went wrong." }],
});

const handleErrorClear = () => {
  clearError({ redirect: "/" }); // Clear error and redirect to homepage
};
</script>

<style scoped>
/* Add styles for your error page */
pre {
  white-space: pre-wrap;
  word-wrap: break-word;
  text-align: left;
  background-color: #f3f3f3;
  padding: 10px;
  margin-top: 20px;
  max-height: 300px;
  overflow-y: auto;
}
</style>

Triggering an Error (Example in a page)​

// pages/test-error.vue
<script setup>
const trigger404 = () => {
  // Use statusCode and statusMessage for known errors like 404
  showError({
    statusCode: 404,
    statusMessage: "Page Not Found Custom Message",
  });
};

const trigger500 = () => {
  // For unexpected server/client errors, pass an Error object
  const err = new Error("Something broke!");
  showError(err);
  // Or just statusCode:
  // showError({ statusCode: 500, statusMessage: 'Internal Server Error'})
};
</script>
<template>
  <button @click="trigger404">Trigger 404</button>
  <button @click="trigger500">Trigger 500 Error</button>
</template>
