Next.js 核心知识点梳理

Next.js 是一个基于 React 的开源 Web 开发框架，用于构建功能完善、性能优异的全栈 Web 应用。它提供了生产环境所需的一系列开箱即用的功能。

1. 路由系统 (Routing)​

Next.js 提供了两种主要的路由系统：Pages Router 和 App Router。App Router 是较新的系统（自 Next.js 13 引入），推荐用于新项目，提供了更灵活的布局和组件模型。

1.1 Pages Router (pages 目录)​

说明​

基于文件的路由系统，位于 pages 目录下。文件和文件夹结构直接映射到 URL 路径。

  • pages/index.js -> /
  • pages/about.js -> /about
  • pages/posts/index.js -> /posts
  • pages/posts/[id].js -> /posts/:id (动态路由)
  • pages/docs/[...slug].js -> /docs/* (捕获所有路由)
  • pages/api/ -> API 路由（见后续章节）

示例代码​

// pages/about.js
import React from 'react';

function AboutPage() {
  return <h1>About Us Page</h1>;
}
export default AboutPage;

// pages/posts/[id].js
import React from 'react';
import { useRouter } from 'next/router';

function PostDetailPage() {
  const router = useRouter();
  const { id } = router.query; // Access dynamic route parameter 'id'

  return <h1>Post Detail Page for ID: {id}</h1>;
}
export default PostDetailPage;

// pages/docs/[...slug].js
import React from 'react';
import { useRouter } from 'next/router';

function DocsCatchAllPage() {
    const router = useRouter();
    const { slug } = router.query; // slug will be an array of path segments

    return <h1>Docs Page: {slug ? slug.join('/') : 'Index'}</h1>;
}
export default DocsCatchAllPage;

1.2 App Router (app 目录)​

说明​

App Router 在 app 目录下工作，引入了基于 React Server Components 的新范式和文件约定。

  • 文件夹定义路由段: app/dashboard/settings -> /dashboard/settings
  • page.js: 定义路由段的 UI，使其公开可访问。
  • layout.js: 定义跨多个子路由段共享的 UI 布局。根布局 app/layout.js 是必需的。
  • loading.js: 为路由段创建加载状态 UI (使用 React Suspense)。
  • error.js: 为路由段创建错误边界 UI，捕获错误并显示回退界面。
  • template.js: 类似于 layout.js，但在导航时会重新挂载，不保留 state。
  • route.js: 定义 API 端点 (替代 Pages Router 的 API Routes)。
  • 动态路由段: app/products/[productId]/page.js -> /products/:productId
  • 捕获所有路由段: app/shop/[...slug]/page.js -> /shop/*
  • 可选捕获所有路由段: app/optional/[[...slug]]/page.js -> /optional/* 和 /optional

示例代码​

}

2. 渲染策略 (Rendering Strategies)​

Next.js 提供了灵活的渲染方式，可在页面（或路由段）级别选择。

2.1 服务器端渲染 (SSR - Server-Side Rendering)​

说明​

页面 HTML 在每次请求时于服务器上生成。适用于需要最新数据且对 SEO 友好的页面。

  • Pages Router: 使用 getServerSideProps 函数。
  • App Router: 默认情况下组件是 Server Components。使用动态函数 (如 headers(), cookies()) 或将 fetch 的 cache 选项设为 'no-store' 会触发动态渲染 (SSR)。

示例代码 (Pages Router - getServerSideProps)​

// pages/ssr-profile.js
import React from "react";

function SsrProfilePage({ user, timestamp }) {
  return (
    <div>
      <h1>Profile (SSR)</h1>
      <p>User: {user.name}</p>
      <p>Generated at: {new Date(timestamp).toLocaleTimeString()}</p>
    </div>
  );
}

export async function getServerSideProps(context) {
  // context contains request-specific params, query, req, res etc.
  const res = await fetch("https://jsonplaceholder.typicode.com/users/1");
  const user = await res.json();

  if (!user) {
    return { notFound: true }; // Return 404 if user not found
  }

  return {
    props: {
      // Passed to the page component as props
      user,
      timestamp: Date.now(), // Example: include generation time
    },
  };
}

export default SsrProfilePage;

示例代码 (App Router - Dynamic Rendering)​

// app/dynamic-data/page.js
import { cookies } from "next/headers"; // Using a dynamic function forces SSR
import React from "react";

async function getDynamicData() {
  // Fetch data without caching, forcing dynamic fetch on every request
  const res = await fetch("https://jsonplaceholder.typicode.com/todos/1", {
    cache: "no-store",
  });
  if (!res.ok) throw new Error("Failed to fetch");
  return res.json();
}

export default async function DynamicDataPage() {
  const cookieStore = cookies(); // Accessing cookies also opts into dynamic rendering
  const theme = cookieStore.get("theme")?.value || "light";
  const data = await getDynamicData();

  return (
    <div>
      <h1>Dynamically Rendered Page</h1>
      <p>Current Theme from Cookie: {theme}</p>
      <p>Fetched Todo Title: {data.title}</p>
    </div>
  );
}

// This page will be server-rendered on each request.
export const dynamic = "force-dynamic"; // Optional: Explicitly force dynamic rendering

2.2 静态站点生成 (SSG - Static Site Generation)​

说明​

页面 HTML 在构建时生成。非常适合性能和 SEO，适用于内容不经常变化的页面（博客、文档、营销页）。

  • Pages Router: 使用 getStaticProps 函数。结合 getStaticPaths 可为动态路由预渲染多个页面。
  • App Router: 默认行为。如果 Server Component 不使用动态函数且其数据获取是静态的 (默认 fetch 缓存)，页面会在构建时静态渲染。使用 generateStaticParams 可为动态路由生成静态页面。

示例代码 (Pages Router - getStaticProps & getStaticPaths)​

// pages/posts-static/[id].js
import React from "react";

function StaticPostPage({ post }) {
  if (!post) return <p>Post not found.</p>;
  return (
    <div>
      <h1>{post.title} (Static)</h1>
      <p>{post.body}</p>
    </div>
  );
}

// Fetch data for a specific post at build time
export async function getStaticProps({ params }) {
  const res = await fetch(
    `https://jsonplaceholder.typicode.com/posts/${params.id}`
  );
  const post = await res.json();

  if (!post.id) {
    // Handle cases where the post doesn't exist at build time
    return { notFound: true };
  }

  return { props: { post } };
}

// Specify which dynamic paths should be pre-rendered at build time
export async function getStaticPaths() {
  const res = await fetch(
    "https://jsonplaceholder.typicode.com/posts?_limit=10"
  );
  const posts = await res.json();
  const paths = posts.map((post) => ({
    params: { id: post.id.toString() },
  }));

  return {
    paths, // Prerender these paths
    fallback: "blocking", // 'blocking': SSR if not generated, then cache. false: 404. true: show fallback UI, generate in background.
  };
}

export default StaticPostPage;

示例代码 (App Router - Static Rendering & generateStaticParams)​

// app/static-products/[productId]/page.js
import React from "react";

// Data fetching defaults to static (cache: 'force-cache')
async function getProduct(productId) {
  const res = await fetch(`https://dummyjson.com/products/${productId}`);
  if (!res.ok) return null;
  return res.json();
}

// Page component is a Server Component, renders statically by default
export default async function StaticProductPage({ params }) {
  const product = await getProduct(params.productId);
  if (!product) return <div>Product not found!</div>;

  return (
    <div>
      <h1>{product.title} (Static)</h1>
      <p>{product.description}</p>
      <p>Price: ${product.price}</p>
    </div>
  );
}

// Equivalent to getStaticPaths: Generate static params at build time
export async function generateStaticParams() {
  const res = await fetch("https://dummyjson.com/products?limit=5&select=id");
  const { products } = await res.json();

  return products.map((product) => ({
    productId: product.id.toString(), // Param name must match folder name [productId]
  }));
}

// This route segment will be statically generated for products 1 through 5 at build time.
// Other product IDs might be generated on demand if not found (depending on config/fallback behavior, though App Router's fallback is different).

2.3 增量静态再生 (ISR - Incremental Static Regeneration)​

说明​

允许在页面构建后，按设定的时间间隔重新生成静态页面，而无需完全重新构建站点。结合了 SSG 的性能和 SSR 的数据新鲜度。

  • Pages Router: 在 getStaticProps 返回对象中设置 revalidate 属性（秒数）。
  • App Router: 在 fetch 调用中设置 next.revalidate 选项，或在页面/布局级别导出 revalidate 常量。

示例代码 (Pages Router)​

// pages/isr-time.js
import React from "react";

function IsrTimePage({ time }) {
  return <h1>ISR Time: {new Date(time).toLocaleTimeString()}</h1>;
}

export async function getStaticProps() {
  // Fetch data or just get current time
  const time = Date.now();
  return {
    props: { time },
    revalidate: 10, // Re-generate the page at most once every 10 seconds
  };
}

export default IsrTimePage;

示例代码 (App Router)​

// app/isr-example/page.js
import React from "react";

async function getRevalidatedData() {
  // Fetch data with revalidation interval
  const res = await fetch("https://worldtimeapi.org/api/ip", {
    next: { revalidate: 5 }, // Revalidate every 5 seconds
  });
  if (!res.ok) throw new Error("Failed to fetch time");
  return res.json();
}

// Or export revalidate constant at page level
// export const revalidate = 5;

export default async function IsrExamplePage() {
  const data = await getRevalidatedData();
  return (
    <div>
      <h1>ISR Example (App Router)</h1>
      <p>
        Current Time (approx): {new Date(data.datetime).toLocaleTimeString()}
      </p>
      <p>Timezone: {data.timezone}</p>
      <p>(This page revalidates every 5 seconds)</p>
    </div>
  );
}

2.4 客户端渲染 (CSR - Client-Side Rendering)​

说明​

内容在浏览器中使用 JavaScript 渲染。适用于需要高度交互、个性化且对初始加载 SEO 要求不高的部分（如用户仪表盘）。

  • Pages Router: 页面不使用 getServerSideProps 或 getStaticProps。通常在 useEffect Hook 中获取数据。
  • App Router: 使用 'use client' 指令将组件标记为 Client Component。Client Components 可以在浏览器中运行，使用 Hooks、事件监听器等。

示例代码 (App Router - Client Component)​

// app/client-dashboard/page.js
"use client"; // Mark this component and its imports as Client Components

import React, { useState, useEffect } from "react";

export default function ClientDashboardPage() {
  const [data, setData] = useState(null);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    setIsLoading(true);
    fetch("/api/dashboard-metrics") // Fetch data client-side from an API route
      .then((res) => {
        if (!res.ok) throw new Error("Network response was not ok");
        return res.json();
      })
      .then((result) => {
        setData(result);
        setIsLoading(false);
      })
      .catch((err) => {
        setError(err.message);
        setIsLoading(false);
      });
  }, []); // Empty dependency array ensures this runs once on mount

  if (isLoading) return <p>Loading dashboard metrics...</p>;
  if (error) return <p>Error loading metrics: {error}</p>;
  if (!data) return <p>No metrics found.</p>;

  return (
    <div>
      <h1>Client-Side Rendered Dashboard</h1>
      <p>Active Users: {data.activeUsers}</p>
      <p>Revenue: ${data.revenue}</p>
      {/* More interactive charts/elements */}
    </div>
  );
}

// Assume you have an API route at app/api/dashboard-metrics/route.js (or pages/api/)

3. App Router: Server Components vs. Client Components​

说明​

App Router 引入了 React Server Components (RSC) 作为核心。

  • Server Components (默认):
    • 在服务器上渲染。
    • 可以直接访问后端资源（数据库、文件系统）、执行 async/await 获取数据。
    • 不能使用 Hooks (useState, useEffect 等) 或浏览器 API (window, document)。
    • 减少发送到客户端的 JavaScript 包大小。
    • 适合静态内容展示、数据获取。
  • Client Components ('use client' 指令):
    • 在客户端渲染（初始 HTML 可由服务器预渲染）。
    • 可以使用 Hooks、状态、生命周期、事件监听器、浏览器 API。
    • 需要交互性或浏览器特定功能的组件必须是 Client Components。
    • 在文件顶部添加 'use client' 指令。一旦标记，其导入的所有子组件（除非是 Server Component 作为 children prop 传入）也会被视为 Client Components。

最佳实践: 尽量将组件保持为 Server Components，仅在需要客户端交互或浏览器 API 时使用 'use client'，并将 Client Components 放在组件树的叶子节点附近。

示例代码 (混合使用)​

// app/server-client-mix/page.js (Server Component by default)
import React from 'react';
import InteractiveButton from './InteractiveButton'; // Import Client Component

async function getServerTime() {
    await new Promise(resolve => setTimeout(resolve, 50)); // Simulate delay
    return new Date().toLocaleTimeString();
}

export default async function ServerClientMixPage() {
    const time = await getServerTime();

    console.log("Rendering ServerClientMixPage on server...");

    return (
        <div>
            <h1>Server and Client Component Mix</h1>
            <p>This part is rendered on the server.</p>
            <p>Server Time: {time}</p>

            {/* Render Client Component within Server Component */}
            <InteractiveButton initialCount={5}>
                {/* You can pass Server Components as children to Client Components */}
                <p>This is a child from the Server Component!</p>
            </InteractiveButton>

            {/* Cannot use hooks or event handlers directly here */}
            {/* <button onClick={() => alert('hi')}>Invalid in Server Component</button> */}
        </div>
    );
}


// app/server-client-mix/InteractiveButton.jsx
'use client'; // Mark as Client Component

import React, { useState, useEffect } from 'react';

export default function InteractiveButton({ initialCount = 0, children }) {
    const [count, setCount] = useState(initialCount);

    useEffect(() => {
        console.log("InteractiveButton mounted on client.");
        // Can use browser APIs here
        // window.alert("Client component ready!") // (Example, maybe annoying)
    }, []);

    const handleClick = () => {
        setCount(prev => prev + 1);
        console.log("Button clicked on client!");
    };

    console.log("Rendering InteractiveButton on client...");

    return (
        <div style={{ border: '1px solid blue', padding: '10px', marginTop: '10px' }}>
            <p>This is the Client Component area.</p>
            <button onClick={handleClick}>
                Clicked {count} times
            </button>
            {/* Render children passed from Server Component */}
            <div style={{ marginTop: '5px', fontStyle: 'italic' }}>
                Children from server: {children}
            </div>
        </div>
    );
}

4. 数据获取 (Data Fetching)​

4.1 Pages Router​

  • getServerSideProps: 请求时获取 (SSR)。
  • getStaticProps: 构建时获取 (SSG/ISR)。
  • getStaticPaths: 指定动态路由的预渲染路径 (SSG/ISR)。
  • 客户端获取: 在 useEffect 中使用 fetch 或库 (SWR, TanStack Query)。

(示例见上方渲染策略部分)

4.2 App Router​

  • Server Components (直接 fetch): 在 Server Components 中直接使用 async/await 和 fetch。
    • 自动缓存: Next.js 扩展了 fetch API，默认情况下会积极缓存请求 (cache: 'force-cache')，行为类似 getStaticProps。
    • 控制缓存:
      • fetch(url, { cache: 'no-store' }): 不缓存，每次请求都重新获取（SSR 行为）。
      • fetch(url, { next: { revalidate: seconds } }): 缓存数据，但设定重新验证时间（ISR 行为）。
  • generateStaticParams: 构建时为动态路由生成参数 (类似 getStaticPaths)。
  • Route Handlers (route.js): 创建 API 端点，供客户端组件 fetch 调用。
  • Server Actions: (稳定) 允许从 Client Components 安全地调用在服务器上定义的异步函数。极大地简化了表单提交和数据变更逻辑，无需手动创建 API 端点。

示例代码 (App Router - fetch 缓存控制)​

// app/fetch-cache-demo/page.js (Server Component)
import React from "react";

async function getCachedData() {
  console.log("Fetching cached data (should happen rarely/at build)...");
  const res = await fetch("https://dummyjson.com/products/2", {
    cache: "force-cache",
  }); // Default
  return res.json();
}

async function getNoStoreData() {
  console.log("Fetching no-store data (should happen on every request)...");
  const res = await fetch("https://dummyjson.com/products/3", {
    cache: "no-store",
  });
  return res.json();
}

async function getRevalidatedData() {
  console.log("Fetching revalidated data (should happen every 10s)...");
  const res = await fetch("https://dummyjson.com/products/4", {
    next: { revalidate: 10 },
  });
  return res.json();
}

export default async function FetchCacheDemoPage() {
  const cached = await getCachedData();
  const noStore = await getNoStoreData();
  const revalidated = await getRevalidatedData();

  return (
    <div>
      <h1>Fetch Cache Demo</h1>
      <h2>Cached (Default): {cached.title}</h2>
      <h2>No Store (Dynamic): {noStore.title}</h2>
      <h2>Revalidated (ISR, 10s): {revalidated.title}</h2>
    </div>
  );
}

示例代码 (App Router - Server Action)​

// app/server-actions-demo/actions.js
'use server'; // Mark functions in this file as Server Actions

import { revalidatePath } from 'next/cache';

// Example: Simulate adding an item to a list (in a real app, interact with DB)
let items = ['Apple', 'Banana'];

export async function addItem(formData) {
    const newItem = formData.get('item'); // Get data from form
    if (newItem && typeof newItem === 'string' && newItem.trim() !== '') {
        console.log("Server Action: Adding item", newItem);
        await new Promise(resolve => setTimeout(resolve, 500)); // Simulate async
        items.push(newItem.trim());
        revalidatePath('/server-actions-demo'); // Revalidate the page to show updated list
        return { success: true, message: `${newItem} added!` };
    } else {
        return { success: false, message: 'Item cannot be empty.' };
    }
}

export async function getItems() {
    console.log("Server Action: Getting items");
    return items;
}


// app/server-actions-demo/ItemForm.jsx
'use client'; // This component handles the form interaction

import React, { useState, useTransition } from 'react';
import { addItem } from './actions'; // Import the Server Action

export default function ItemForm() {
    const [message, setMessage] = useState('');
    const [isPending, startTransition] = useTransition(); // Handle pending state

    const handleSubmit = async (event) => {
        event.preventDefault();
        const formData = new FormData(event.currentTarget);

        startTransition(async () => {
            const result = await addItem(formData); // Call the server action directly
            setMessage(result.message);
            if (result.success) {
                event.target.reset(); // Reset form on success
            }
        });
    };

    return (
        <form onSubmit={handleSubmit}>
            <input type="text" name="item" placeholder="New Item" disabled={isPending} required />
            <button type="submit" disabled={isPending}>
                {isPending ? 'Adding...' : 'Add Item'}
            </button>
            {message && <p>{message}</p>}
        </form>
    );
}


// app/server-actions-demo/page.js (Server Component to display items)
import React from 'react';
import ItemForm from './ItemForm';
import { getItems } from './actions'; // Import action to get data

export default async function ServerActionsPage() {
    const currentItems = await getItems(); // Call action on server to get initial data

    return (
        <div>
            <h1>Server Actions Demo</h1>
            <h2>Add Item</h2>
            <ItemForm />
            <h2>Current Items</h2>
            <ul>
                {currentItems.map((item, index) => <li key={index}>{item}</li>)}
            </ul>
            {currentItems.length === 0 && <p>No items yet.</p>}
        </div>
    );
}

5. 导航 (Navigation)​

5.1 <Link> Component (next/link)​

说明​

用于在 Next.js 应用的不同页面之间进行客户端导航。它会自动预取链接页面的代码（在视口内时），实现快速、平滑的页面过渡，无需整页刷新。适用于 Pages Router 和 App Router。

示例代码​

import React from "react";
import Link from "next/link";

function NavigationMenu() {
  const postId = 5;
  return (
    <nav>
      <ul style={{ listStyle: "none", display: "flex", gap: "15px" }}>
        <li>
          <Link href="/">Home</Link>
        </li>
        <li>
          <Link href="/about">About</Link>
        </li>
        {/* Dynamic route link */}
        <li>
          <Link href={`/posts-static/${postId}`}>Post {postId} (Static)</Link>
        </li>
        {/* Link within App Router */}
        <li>
          <Link href="/dashboard/settings">Dashboard Settings</Link>
        </li>
        {/* Disable prefetching */}
        <li>
          <Link href="/contact" prefetch={false}>
            Contact (No Prefetch)
          </Link>
        </li>
        {/* Add attributes like className */}
        <li>
          <Link href="/ssr-profile" className="nav-link">
            SSR Profile
          </Link>
        </li>
      </ul>
    </nav>
  );
}
export default NavigationMenu;

说明​

用于在函数组件中以编程方式进行导航（如表单提交后跳转）或访问路由信息（路径名、查询参数）。

示例代码 (Pages Router)​

// components/LoginButton.jsx (Pages Router example)

function LoginButton() {

5.3 Navigation Hooks (App Router - next/navigation)​

说明​

App Router 提供了专门的 Hooks 来处理导航和路由状态。

  • useRouter(): 提供 push, replace, refresh, back, forward 方法。refresh() 可在不丢失客户端状态的情况下刷新当前路由，重新获取服务器数据并渲染 Server Components。
  • usePathname(): 返回当前 URL 的路径名字符串。
  • useSearchParams(): 返回当前 URL 查询参数的只读 URLSearchParams 接口。
  • useParams(): 返回包含当前路由动态参数的对象。

示例代码 (App Router)​

// app/products/ProductSearch.jsx
"use client";

import React, { useState } from "react";
import { useRouter, usePathname, useSearchParams } from "next/navigation";

export default function ProductSearch() {
  const router = useRouter();
  const pathname = usePathname(); // e.g., "/products"
  const searchParams = useSearchParams(); // Readonly access to query params
  const currentQuery = searchParams.get("q");

  const [searchTerm, setSearchTerm] = useState(currentQuery || "");

  const handleSearch = (event) => {
    event.preventDefault();
    const params = new URLSearchParams(searchParams); // Create mutable copy
    if (searchTerm) {
      params.set("q", searchTerm);
    } else {
      params.delete("q");
    }
    // Navigate with new query params
    router.push(`${pathname}?${params.toString()}`);
  };

  const refreshData = () => {
    console.log("Refreshing server data for current route...");
    router.refresh(); // Re-fetches data for the current route
  };

  return (
    <div>
      <form onSubmit={handleSearch}>
        <input
          type="text"
          placeholder="Search products..."
          value={searchTerm}
          onChange={(e) => setSearchTerm(e.target.value)}
        />
        <button type="submit">Search</button>
      </form>
      <button onClick={refreshData} style={{ marginLeft: "10px" }}>
        Refresh Data
      </button>
      <p>Current Path: {pathname}</p>
      <p>Current Search: {currentQuery || "None"}</p>
    </div>
  );
}

6. API 路由 / Route Handlers​

说明​

允许你在 Next.js 应用内部创建 API 端点，处理来自客户端或其他服务的请求。

  • Pages Router: 在 pages/api 目录下创建文件。导出一个默认函数，该函数接收 req (NextApiRequest) 和 res (NextApiResponse) 对象。
  • App Router: 在 app 目录下创建 route.js 文件。导出对应 HTTP 方法的大写命名函数（GET, POST, PUT, DELETE 等），这些函数接收 request (Request) 对象，并应返回 Response 或 NextResponse 对象。NextResponse 是 Response 的扩展，提供了一些便利方法（如 json()）。

示例代码 (Pages Router - API Route)​

// pages/api/hello.js
import type { NextApiRequest, NextApiResponse } from "next";

type ResponseData = {
  message: string,
};

export default function handler(
  req: NextApiRequest,
  res: NextApiResponse<ResponseData>
) {
  if (req.method === "GET") {
    const name = req.query.name || "World";
    res.status(200).json({ message: `Hello, ${name}!` });
  } else {
    res.setHeader("Allow", ["GET"]);
    res.status(405).end(`Method ${req.method} Not Allowed`);
  }
}

示例代码 (App Router - Route Handler)​

// app/api/items/route.js
import { NextResponse } from "next/server";

let items = [{ id: 1, name: "Default Item" }]; // In-memory store (for demo)

// Handle GET requests
export async function GET(request: Request) {
  // You can access query params from the request URL
  const { searchParams } = new URL(request.url);
  const limit = searchParams.get("limit");

  let responseItems = items;
  if (limit && !isNaN(parseInt(limit))) {
    responseItems = items.slice(0, parseInt(limit));
  }

  console.log("API GET /api/items called");
  return NextResponse.json(responseItems);
}

// Handle POST requests
export async function POST(request: Request) {
  try {
    const body = await request.json(); // Parse JSON body
    if (!body.name) {
      return NextResponse.json(
        { error: "Item name is required" },
        { status: 400 }
      );
    }
    const newItem = { id: Date.now(), name: body.name };
    items.push(newItem);
    console.log("API POST /api/items called, added:", newItem);
    return NextResponse.json(newItem, { status: 201 }); // Return created item with 201 status
  } catch (error) {
    return NextResponse.json({ error: "Invalid JSON body" }, { status: 400 });
  }
}

7.2 图片组件 (next/image)​

说明​

next/image 组件是 HTML <img> 标签的优化版本。它提供：

  • 自动尺寸优化: 根据设备提供适当大小的图片。
  • 视觉稳定性: 防止布局偏移 (CLS)。
  • 按需加载: 图片默认懒加载 (进入视口时加载)。
  • 格式优化: 自动提供 WebP 等现代格式（如果浏览器支持）。
  • 必须提供 width 和 height（对于本地图片会自动推断，对于远程图片必须手动指定），或使用 fill 属性。
  • 远程图片需要在 next.config.js 中配置允许的域名。

示例代码​

// components/OptimizedImage.jsx
import React from "react";
import Image from "next/image";
// Import local image (width/height inferred)
import localHeroImage from "../public/images/hero.jpg";

function OptimizedImage() {
  return (
    <div>
      <h2>Optimized Images with next/image</h2>

      {/* Local Image */}
      <Image
        src={localHeroImage}
        alt="Beautiful landscape"
        placeholder="blur" // Optional: Show low-res blurred placeholder while loading
        style={{ maxWidth: "100%", height: "auto" }} // Make it responsive
      />

      <hr />

      {/* Remote Image */}
      <Image
        src="https://images.unsplash.com/photo-1..." // Replace with actual URL
        alt="Remote image description"
        width={500} // Required for remote images
        height={300} // Required for remote images
        priority // Optional: Preload image if it's LCP (Largest Contentful Paint)
      />

      <hr />

      {/* Fill Example */}
      <div style={{ position: "relative", width: "100%", height: "200px" }}>
        <Image
          src="/images/background.png" // From public folder
          alt="Background texture"
          fill // Fills the parent container
          style={{ objectFit: "cover" }} // Optional: control how image fits
        />
        <h3
          style={{
            position: "relative",
            color: "white",
            zIndex: 1,
            padding: "10px",
          }}
        >
          Text over fill image
        </h3>
      </div>
    </div>
  );
}

8.3 Tailwind CSS​

说明​

Next.js 对流行的工具类优先 CSS 框架 Tailwind CSS 提供了一流的支持。通过 PostCSS 轻松集成。

配置与使用 (简要)​

  3. 配置 tailwind.config.js 中的 content 路径。
  4. 在 styles/globals.css 中导入 Tailwind 指令 (@tailwind base; @tailwind components; @tailwind utilities;)。

示例代码​

// components/Alert.jsx
import React from "react";

function Alert({ message, type = "info" }) {

  };

  return (
    <div className={`${baseStyle} ${typeStyles[type]}`} role="alert">
      <span className="block sm:inline">{message}</span>
    </div>
  );
}

9.2 App Router (Metadata API)​

说明​

App Router 引入了新的 Metadata API，允许通过导出 metadata 对象或 generateMetadata 函数来定义和管理元数据，支持静态和动态生成，并能继承父级布局的元数据。

  • 静态元数据: 在 layout.js 或 page.js 中导出 metadata 对象。
  • 动态元数据: 导出异步函数 generateMetadata({ params, searchParams }, parent)，可根据路由参数或获取的数据生成元数据，并可访问父级解析后的元数据 (parent)。

示例代码​

// app/blog/[slug]/page.js
import React from "react";

// Assume getPostBySlug fetches post data including title, description etc.
async function getPostBySlug(slug) {
  // Replace with your actual data fetching logic
  if (slug === "my-first-post") {
    return {
      title: "My First Blog Post",
      description: "This is the summary...",
      content: "...",
    };
  }
  return null;
}

// Dynamic Metadata Generation
export async function generateMetadata({ params, searchParams }, parent) {
  const slug = params.slug;
  const post = await getPostBySlug(slug);

  if (!post) {
    return { title: "Post Not Found" }; // Basic title if not found
  }

  // Optionally access resolved metadata from parent layouts
  const previousKeywords = (await parent).keywords || [];

  return {
    title: `${post.title} | My Blog`,
    description: post.description,
    keywords: ["blog", post.title, ...previousKeywords], // Combine keywords
    openGraph: {
      title: post.title,
      description: post.description,
      // images: [`/images/blog/${slug}.jpg`], // Example OG image
    },
    //alternates: { // Example for canonical URL
    //  canonical: `/blog/${slug}`,
    //}
  };
}

export default async function BlogPostPage({ params }) {
  const post = await getPostBySlug(params.slug);

  if (!post) return <div>Post not found!</div>;

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </article>
  );
}

11. Middleware (middleware.js / middleware.ts)​

说明​

Middleware 允许你在请求完成之前运行代码，基于请求修改响应（重写 URL、重定向、添加/修改请求/响应头）或直接响应。它在 Edge Runtime 上运行，速度快但 API 受限。

在项目的根目录或 src/ 目录下创建 middleware.js (或 .ts) 文件。使用 config 对象中的 matcher 属性指定 Middleware 应用的路径。

示例代码​

// middleware.ts (at root or src/)
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl;
  const requestHeaders = new Headers(request.headers); // Clone headers

  // Example 1: Basic Authentication for staging environment
  const basicAuth = request.headers.get("authorization");
  const url = request.nextUrl;
  if (url.hostname.includes("staging.myapp.com")) {
    // Apply only on staging
    if (basicAuth) {
      const authValue = basicAuth.split(" ")[1];
      const [user, pwd] = atob(authValue).split(":"); // Decode Base64
      const expectedUser = process.env.BASIC_AUTH_USER;
      const expectedPwd = process.env.BASIC_AUTH_PASSWORD;

      if (user === expectedUser && pwd === expectedPwd) {
        return NextResponse.next(); // Authorized
      }
    }
    url.pathname = "/api/auth-required"; // Redirect to an auth required page/API
    return NextResponse.rewrite(url);
    // Or return a 401 response directly
    // return new Response('Auth required', { status: 401, headers: { 'WWW-Authenticate': 'Basic realm="Secure Area"' }});
  }

  // Example 2: Add a custom header
  requestHeaders.set("x-pathname", pathname);
  console.log(`Middleware: Processing ${pathname}`);

  // Example 3: Redirect based on geo location (example header)
  const country = request.geo?.country?.toLowerCase() || "us";
  if (pathname === "/" && country === "ca") {
    console.log("Middleware: Redirecting CA user to /ca");
    return NextResponse.redirect(new URL("/ca", request.url));
  }

  // Continue processing the request with potentially modified headers
  return NextResponse.next({
    request: {
      headers: requestHeaders,
    },
  });
}

// Define which paths this middleware should run on
export const config = {
  matcher: [
    /*
     * Match all request paths except for the ones starting with:
     * - api (API routes)
     * - _next/static (static files)
     * - _next/image (image optimization files)
     * - favicon.ico (favicon file)
     * - Health check paths etc.
     */
    "/((?!api|_next/static|_next/image|favicon.ico|healthz).*)",
    // Or specific paths:
    // '/dashboard/:path*',
    // '/'
  ],
};
