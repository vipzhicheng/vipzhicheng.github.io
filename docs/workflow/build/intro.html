前端构建工具核心知识

一、 为什么需要构建工具？​

在现代前端开发中，我们面临许多工程化挑战，构建工具的出现正是为了解决这些问题：

  1. 模块化开发支持：原生浏览器早期对模块化支持不佳 (CommonJS, AMD)，需要工具将多个模块文件打包成浏览器可识别的单个或少数几个文件。虽然现在有 ES Modules (ESM)，但为了兼容性、依赖管理和优化，打包仍然常见。
  2. 代码转换与编译：
    • ES Next -> ES5/ES6：使用 Babel 等工具将最新的 JavaScript 语法转换为向后兼容的语法，确保在旧版浏览器上运行。
    • TypeScript/CoffeeScript -> JavaScript：将 TypeScript、CoffeeScript 等语言编译成 JavaScript。
    • CSS 预处理器/后处理器：将 Sass/Less/Stylus 编译成 CSS，使用 PostCSS 添加浏览器前缀、进行 CSS Modules 处理等。
  3. 代码优化与压缩：
    • JS/CSS/HTML 压缩：移除空格、注释、缩短变量名，减小文件体积。
    • 图片压缩：优化图片大小。
    • Tree Shaking：移除未使用的代码 (Dead Code Elimination)，主要针对 ESM。
    • 代码分割 (Code Splitting)：将代码拆分成多个块 (chunks)，按需加载，提高首屏加载速度。
  4. 资源管理与定位：
    • 处理 CSS、图片、字体等静态资源，根据配置进行内联 (Data URL)、拷贝或重命名 (添加 hash)。
    • 自动处理文件引用路径。
  5. 开发体验提升：
    • 本地开发服务器：提供带热更新 (HMR - Hot Module Replacement) 或实时刷新 (Live Reload) 功能的开发服务器。
    • Source Maps：将编译/压缩后的代码映射回源代码，方便调试。
    • 统一的开发/生产环境构建流程。
  6. 自动化任务：执行代码检查 (Linting)、单元测试、文件清理、部署等自动化流程。

二、 构建工具的核心概念​

这些概念贯穿于大多数现代构建工具中：

  1. Entry (入口)：

    • 说明：构建过程的起点。构建工具从入口文件开始，递归地查找所有依赖的模块和资源。可以是一个或多个入口。

    • 示例 (Webpack)：

      // webpack.config.js
      module.exports = {
        entry: "./src/index.js", // 单入口
        // 或
        // entry: { // 多入口
        //   main: './src/main.js',
        //   admin: './src/admin.js'
        // }
      };
      // src/index.js (入口文件)
      import { log } from "./utils.js";
      import "./styles.css";

      log("Hello from index.js!");

  2. Output (输出)：

    • 说明：指定构建结果（通常称为 bundles）存放的位置和文件名。可以配置路径、文件名、公共路径 (publicPath) 等。

    • 示例 (Webpack)：

      // webpack.config.js
      const path = require("path");

      module.exports = {
        entry: "./src/index.js",
        output: {
          path: path.resolve(__dirname, "dist"), // 输出目录
          filename: "bundle.js", // 单入口输出文件名
          // 或对于多入口：
          // filename: '[name].[contenthash].js', // 使用占位符，[name]对应入口名，[contenthash]用于缓存控制
          publicPath: "/", // 部署时资源的基础路径
          clean: true, // 在生成文件之前清空 output 目录 (Webpack 5+)
        },
      };

  3. Loaders (加载器) / Transforms (转换器)：

    • 说明：让构建工具能够处理非 JavaScript 文件（如 CSS, 图片, TS, JSX）或对 JavaScript 文件进行转换（如 Babel 转译）。它们在模块加载时按顺序执行。Webpack 中称为 Loaders，其他工具可能叫 Transforms 或有类似机制。
    • 示例 (Webpack)：处理 CSS 和 使用 Babel 转译 JS 
      npm install --save-dev css-loader style-loader babel-loader @babel/core @babel/preset-env
      // webpack.config.js
      module.exports = {
        // ... entry, output
        module: {
          rules: [
            {
              test: /\.css$/i, // 匹配 .css 文件
              use: ["style-loader", "css-loader"], // 应用 loader，注意顺序：从右到左/从下到上
            },
            {
              test: /\.m?js$/, // 匹配 .js 或 .mjs 文件
              exclude: /node_modules/, // 排除 node_modules 目录
              use: {
                loader: "babel-loader",
                options: {
                  presets: ["@babel/preset-env"], // 使用预设进行转译
                },
              },
            },
          ],
        },
      };
      /* src/styles.css */
      body {
        background-color: lightblue;
      }
      // src/utils.js
      export const log = (message) => {
        console.log(`[LOG] ${message}`);
        // 使用 ES6+ 语法，将被 Babel 转译
        const obj = { a: 1, b: 2 };
        const { a, ...rest } = obj;
        console.log("Rest:", rest);
      };

  4. Plugins (插件)：

    • 说明：用于扩展构建工具的功能，执行更广泛的任务，如打包优化、资源管理、环境变量注入等。Loader 用于转换特定类型的文件，而 Plugin 可以贯穿整个构建生命周期。

    • 示例 (Webpack)：自动生成 HTML 文件并注入打包后的 JS

      npm install --save-dev html-webpack-plugin
      // webpack.config.js
      const HtmlWebpackPlugin = require("html-webpack-plugin");

      module.exports = {
        // ... entry, output, module
        plugins: [
          new HtmlWebpackPlugin({
            template: "./src/index.html", // 使用模板 HTML 文件
            title: "My App", // 可以传递变量给模板
          }),
        ],
      };
      <!-- src/index.html -->
      <!DOCTYPE html>
      <html>
        <head>
          <meta charset="utf-8" />
          <title><%= htmlWebpackPlugin.options.title %></title>
        </head>
        <body>
          <div id="root"></div>
          <!-- bundle.js 会被自动注入 -->
        </body>
      </html>

  5. Mode (模式)：

    • 说明：通常分为 development (开发模式) 和 production (生产模式)。构建工具会根据模式自动启用不同的优化和配置。开发模式注重构建速度和调试体验，生产模式注重代码体积和性能。

    • 示例 (Webpack)：

      • 通过 mode 配置项：

        // webpack.config.js
        module.exports = {
          mode: "production", // 或 'development'
          // ...
        };

      • 通过 CLI 参数：

        npx webpack --mode=production
        npx webpack --mode=development

      • 区分配置：

        // webpack.dev.js
        const { merge } = require("webpack-merge");
        const common = require("./webpack.common.js");

        module.exports = merge(common, {
          mode: "development",
          devtool: "inline-source-map", // 开启 source map
          devServer: {
            // 配置开发服务器
            static: "./dist",
            hot: true, // 开启 HMR
          },
        });
        // webpack.prod.js
        const { merge } = require("webpack-merge");
        const common = require("./webpack.common.js");
        const TerserPlugin = require("terser-webpack-plugin"); // 用于压缩 JS

        module.exports = merge(common, {
          mode: "production",
          devtool: "source-map", // 生产环境 source map
          optimization: {
            minimize: true, // 开启压缩
            minimizer: [new TerserPlugin()], // 使用 Terser 压缩 JS
            splitChunks: {
              // 代码分割示例
              chunks: "all",
            },
          },
        });
        // webpack.common.js (公共配置)
        const path = require("path");
        const HtmlWebpackPlugin = require("html-webpack-plugin");

        module.exports = {
          entry: "./src/index.js",
          output: {
            filename: "[name].[contenthash].js",
            path: path.resolve(__dirname, "dist"),
            publicPath: "/",
            clean: true,
          },
          module: {
            /* ... loaders ... */
          },
          plugins: [new HtmlWebpackPlugin({ template: "./src/index.html" })],
        };
        // package.json scripts
        "scripts": {
          "start": "webpack serve --open --config webpack.dev.js",
          "build": "webpack --config webpack.prod.js"
        }

  6. Dependency Graph (依赖图)：

    • 说明：构建工具从入口文件开始，分析代码中的 import, require, @import (CSS) 等语句，找出所有直接和间接的依赖关系，形成一个图状结构。这个图是进行打包、优化（如 Tree Shaking）的基础。
    • 示例 (概念性)： 
      index.js -> utils.js
               -> styles.css -> normalize.css
               -> api.js -> config.js

  7. Tree Shaking (摇树优化)：

    • 说明：一种死代码消除 (Dead Code Elimination) 技术，特别是在 ES Modules 静态结构下效果显著。它能移除 JavaScript 上下文中未引用（未使用）的代码（如未被 import 或使用的 export）。通常在生产模式下自动启用。

    • 示例：

      // src/math.js
      export function square(x) {
        // 会被打包
        return x * x;
      }
      export function cube(x) {
        // 如果 index.js 未导入，会被移除
        return x * x * x;
      }
      // src/index.js
      import { square } from "./math.js"; // 只导入了 square

      console.log(square(5));
      • 在生产构建 (mode: 'production') 后，cube 函数的代码将不会包含在最终的 bundle 中。

  8. Code Splitting (代码分割)：

    • 说明：将代码库分割成多个按需加载的块 (chunks)，而不是生成一个巨大的 bundle 文件。这可以显著提高应用的初始加载速度。常见的分割策略有：按入口点分割、防止重复（提取公共模块）、动态导入 (import())。
    • 示例 (Webpack - 动态导入)： 
      // src/index.js
      const button = document.createElement("button");
      button.textContent = "Load Moment.js";
      button.onclick = () => {
        // 使用动态 import()，会触发代码分割
        import(/* webpackChunkName: "moment" */ "moment")
          .then(({ default: moment }) => {
            console.log("Moment.js loaded:", moment().format());
          })
          .catch((err) => console.error("Failed to load moment", err));
      };
      document.body.appendChild(button);
      • Webpack 会将 moment 库及其依赖打包成一个单独的 chunk 文件 (e.g., moment.[contenthash].js)，只有在按钮被点击时才会下载和执行。
    • 示例 (Webpack - SplitChunksPlugin 自动分割)： 
      // webpack.prod.js
      module.exports = {
        // ...
        mode: "production",
        optimization: {
          splitChunks: {
            chunks: "all", // 对所有类型的 chunks 进行分割 (initial, async)
            cacheGroups: {
              // 定义缓存组，用于更细粒度的控制
              vendor: {
                // 将 node_modules 中的模块提取到单独的 vendor chunk
                test: /[\\/]node_modules[\\/]/,
                name: "vendors",
                chunks: "all",
              },
            },
          },
        },
      };

  9. Source Maps (源映射)：

    • 说明：一个信息文件，它将转换后（压缩、合并、编译）的代码映射回其原始源文件。这使得在浏览器开发者工具中调试时，看到和断点的是原始代码，而不是难以理解的转换后代码。
    • 示例 (Webpack)： 
      // webpack.dev.js
      module.exports = {
        mode: "development",
        devtool: "eval-source-map", // 开发环境：构建快，信息全
        // ...
      };
      // webpack.prod.js
      module.exports = {
        mode: "production",
        devtool: "source-map", // 生产环境：信息全，但会生成单独的 .map 文件，较慢
        // 或 'hidden-source-map' (不暴露给浏览器，用于错误报告)
        // 或 false (不生成 source map)
        // ...
      };

  10. Development Server (开发服务器)：

    • 说明：在开发期间运行的一个本地服务器，提供实时预览、自动刷新或热模块替换 (HMR) 功能。

    • HMR (Hot Module Replacement)：在应用运行时，无需完全刷新页面，即可替换、添加或删除模块。这可以显著提高开发效率，尤其是在调整 UI 或保留应用状态时。

    • 示例 (Webpack Dev Server)：

      npm install --save-dev webpack-dev-server
      // webpack.dev.js
      module.exports = {
        // ...
        mode: "development",
        devServer: {
          static: "./dist", // 提供静态文件的目录
          hot: true, // 启用 HMR
          open: true, // 自动打开浏览器
          port: 8080, // 指定端口
        },
      };
      // package.json scripts
      "scripts": {
        "start": "webpack serve --config webpack.dev.js"
      }
      • 对于 HMR，有时需要在入口文件或特定模块中添加接受更新的逻辑（例如，React Fast Refresh, Vue Loader 会自动处理大部分情况）。
      // src/index.js (简单示例，框架通常自带处理)
      import { printMe } from "./print.js";
      import "./styles.css";

      function component() {
        const element = document.createElement("div");
        element.innerHTML = "Hello webpack!";
        const btn = document.createElement("button");
        btn.innerHTML = "Click me and check the console!";
        btn.onclick = printMe;
        element.appendChild(btn);
        return element;
      }

      let element = component(); // Store the element to re-render on print.js changes
      document.body.appendChild(element);

      // HMR Interface (简单示例)
      if (module.hot) {
        module.hot.accept("./print.js", function () {
          console.log("Accepting the updated printMe module!");
          // 需要手动处理更新逻辑，例如重新绑定事件或重新渲染组件
          document.body.removeChild(element); // 移除旧元素
          element = component(); // 重新创建组件
          document.body.appendChild(element); // 添加新元素
        });
      }
      // src/print.js
      export function printMe() {
        console.log("I get called from print.js! Update this message.");
        // console.log('Updating print.js again...'); // 修改这里，查看 HMR 效果
      }

三、 主流构建工具梳理​

1. Task Runners (任务运行器) - Grunt / Gulp (早期代表)​

  • 核心思想：自动化前端开发中的重复性任务（如压缩、编译、合并、检查等）。它们不直接处理模块依赖，而是通过配置一系列任务及其执行顺序。

  • Grunt:

    • 特点：配置驱动，基于 JSON 文件 (Gruntfile.js) 定义任务。任务通常是原子性的，读写文件是其主要操作，中间产物常写入临时文件。

    • 示例 (Gruntfile.js):

      module.exports = function (grunt) {
        // Project configuration.
        grunt.initConfig({
          pkg: grunt.file.readJSON("package.json"),
          concat: {
            // 合并文件任务
            options: {
              separator: ";",
            },
            dist: {
              src: ["src/**/*.js"], // 目标文件
              dest: "dist/<%= pkg.name %>.js", // 输出文件
            },
          },
          uglify: {
            // 压缩 JS 任务
            options: {
              banner:
                '/*! <%= pkg.name %> <%= grunt.template.today("yyyy-mm-dd") %> */\n',
            },
            build: {
              src: "dist/<%= pkg.name %>.js", // 输入文件 (来自 concat 任务)
              dest: "dist/<%= pkg.name %>.min.js", // 输出压缩文件
            },
          },
          watch: {
            // 监听文件变化任务
            scripts: {
              files: ["src/**/*.js"],
              tasks: ["concat", "uglify"], // 文件变化时执行的任务
              options: {
                spawn: false,
              },
            },
          },
        });

        // 加载提供任务的插件
        grunt.loadNpmTasks("grunt-contrib-concat");
        grunt.loadNpmTasks("grunt-contrib-uglify");
        grunt.loadNpmTasks("grunt-contrib-watch");

        // 默认被执行的任务列表
        grunt.registerTask("default", ["concat", "uglify"]);
        // 定义开发任务
        grunt.registerTask("dev", ["default", "watch"]);
      };
      npm install grunt grunt-contrib-concat grunt-contrib-uglify grunt-contrib-watch --save-dev
      grunt # 执行 default 任务
      grunt dev # 执行 dev 任务 (包含监听)

  • Gulp:

    • 特点：代码优于配置，使用 JavaScript 代码 (gulpfile.js) 编写任务。利用 Node.js Streams（流）处理文件，避免了频繁的 I/O 操作，通常比 Grunt 更快。任务可以通过 .pipe() 链式调用。

    • 示例 (gulpfile.js):

      const gulp = require("gulp");
      const concat = require("gulp-concat");
      const uglify = require("gulp-uglify");
      const rename = require("gulp-rename");
      const watch = require("gulp-watch"); // or gulp.watch in Gulp 4+

      // Gulp 4+ 语法
      function scripts() {
        return gulp
          .src("src/**/*.js") // 获取源文件流
          .pipe(concat("app.js")) // 合并到一个文件
          .pipe(gulp.dest("dist")) // 输出未压缩版本
          .pipe(uglify()) // 压缩 JS
          .pipe(rename("app.min.js")) // 重命名为 .min.js
          .pipe(gulp.dest("dist")); // 输出压缩版本
      }

      function watchFiles() {
        gulp.watch("src/**/*.js", scripts); // 监听 JS 文件变化，执行 scripts 任务
      }

      const build = gulp.series(scripts); // 定义 build 任务
      const dev = gulp.series(scripts, watchFiles); // 定义 dev 任务

      exports.scripts = scripts;
      exports.watch = watchFiles;
      exports.build = build;
      exports.default = build; // 默认任务
      exports.dev = dev;
      npm install gulp gulp-concat gulp-uglify gulp-rename --save-dev
      gulp # 执行 default (build) 任务
      gulp dev # 执行 dev 任务 (包含监听)

2. Module Bundlers (模块打包器) - Webpack​

  • 核心思想：将项目视为一个依赖图，从入口点出发，解析并打包所有模块（JS, CSS, 图片等）及其依赖项，生成优化后的静态资源。是目前功能最强大、生态最完善的构建工具之一。

  • 特点：

    • 高度可配置，通过 webpack.config.js 文件。
    • 强大的 Loader 和 Plugin 系统，生态极其丰富。
    • 支持代码分割、Tree Shaking、HMR、各种模块化标准 (ESM, CJS, AMD)。
    • 适用于大型复杂单页应用 (SPA)。
    • 学习曲线相对陡峭。

  • 核心配置项回顾: entry, output, module.rules (Loaders), plugins, mode, devServer, optimization, devtool, resolve (模块解析配置)。

  • 示例 (webpack.config.js - 较完整):

    # 安装依赖
    npm install webpack webpack-cli webpack-dev-server --save-dev
    npm install --save-dev html-webpack-plugin clean-webpack-plugin
    npm install --save-dev style-loader css-loader sass-loader sass # 处理 SCSS
    npm install --save-dev babel-loader @babel/core @babel/preset-env @babel/preset-react # 处理 React JSX 和 ES6+
    npm install --save react react-dom # 示例应用依赖
    // webpack.config.js
    const path = require("path");
    const HtmlWebpackPlugin = require("html-webpack-plugin");
    const { CleanWebpackPlugin } = require("clean-webpack-plugin");
    // const MiniCssExtractPlugin = require('mini-css-extract-plugin'); // 用于提取 CSS 到单独文件

    module.exports = (env, argv) => {
      const isProduction = argv.mode === "production";

      return {
        mode: isProduction ? "production" : "development",
        entry: {
          main: "./src/index.js",
        },
        output: {
          filename: isProduction ? "[name].[contenthash].js" : "[name].bundle.js",
          path: path.resolve(__dirname, "dist"),
          publicPath: "/",
          assetModuleFilename: "assets/[hash][ext][query]", // 统一资源输出路径 (Webpack 5+)
          clean: true, // 替代 CleanWebpackPlugin
        },
        devtool: isProduction ? "source-map" : "eval-source-map",
        devServer: {
          static: "./dist",
          historyApiFallback: true, // 支持 SPA 路由
          hot: true,
          open: true,
          port: 3000,
        },
        module: {
          rules: [
            // JavaScript / JSX
            {
              test: /\.(js|jsx)$/,
              exclude: /node_modules/,
              use: {
                loader: "babel-loader",
                options: {
                  presets: ["@babel/preset-env", "@babel/preset-react"],
                },
              },
            },
            // CSS / SCSS
            {
              test: /\.s?css$/,
              use: [
                // isProduction ? MiniCssExtractPlugin.loader : 'style-loader', // 生产环境提取 CSS，开发环境注入 style 标签
                "style-loader", // 简单起见，始终用 style-loader
                "css-loader", // 解析 CSS 文件中的 @import 和 url()
                "sass-loader", // 将 Sass/SCSS 编译为 CSS
              ],
            },
            // Images (Webpack 5 Asset Modules)
            {
              test: /\.(png|svg|jpg|jpeg|gif)$/i,
              type: "asset/resource", // 发送独立文件并导出 URL
            },
            // Fonts (Webpack 5 Asset Modules)
            {
              test: /\.(woff|woff2|eot|ttf|otf)$/i,
              type: "asset/resource",
            },
            // Data (e.g., CSV, XML) (Webpack 5 Asset Modules)
            // {
            //   test: /\.(csv|tsv)$/i,
            //   use: ['csv-loader'],
            // },
            // {
            //   test: /\.xml$/i,
            //   use: ['xml-loader'],
            // },
          ],
        },
        plugins: [
          // new CleanWebpackPlugin(), // Webpack 5 output.clean 替代
          new HtmlWebpackPlugin({
            template: "./public/index.html", // 指定 HTML 模板
            favicon: "./public/favicon.ico", // 指定 favicon
          }),
          // new MiniCssExtractPlugin({ // 生产环境启用

3. Next Generation Bundlers (新一代构建工具)​

这些工具旨在解决 Webpack 的一些痛点，如构建速度慢、配置复杂等。

a. Vite​

  • 核心思想：利用浏览器原生 ES Modules (ESM) 支持和 Go 编写的 esbuild 来实现极快的冷启动和 HMR 速度。

    • 开发环境：启动一个服务器，对源码进行按需编译和提供。浏览器通过 <script type="module"> 请求源码，Vite 只编译当前请求的模块，无需预先打包整个应用。HMR 也是基于 ESM，更新速度极快。
    • 生产环境：使用 Rollup 进行打包，以获得更好的优化（如 Tree Shaking, 代码分割）。

  • 特点：

    • 极快的冷启动速度和 HMR。
    • 开箱即用，对 TS, JSX, CSS (Modules, PostCSS) 等有良好内置支持。
    • 配置简单 (vite.config.js 或 .ts)，基于 Rollup 的插件接口。
    • 面向现代浏览器，默认输出 ESM。
    • 优秀的开发体验。

  • 示例 (vite.config.js):

    npm create vite@latest my-vite-app --template react # 创建 React + Vite 项目
    cd my-vite-app
    npm install
    npm run dev # 启动开发服务器
    npm run build # 构建生产版本
    // vite.config.js (通常不需要太多配置)
    import { defineConfig } from "vite";
    import react from "@vitejs/plugin-react"; // React 插件，提供 Fast Refresh 等
    import path from "path";

    // https://vitejs.dev/config/
    export default defineConfig({
      plugins: [react()],
      resolve: {
        alias: {
          // 配置别名
          "@": path.resolve(__dirname, "./src"),
        },
      },
      server: {
        // 开发服务器配置
        port: 3000,
        open: true,
        // proxy: { // 配置代理，解决跨域问题
        //   '/api': {
        //     target: 'http://jsonplaceholder.typicode.com',
        //     changeOrigin: true,
        //     rewrite: (path) => path.replace(/^\/api/, ''),
        //   },
        // }
      },
      build: {
        // 生产构建配置
        sourcemap: true, // 生成 source map
        rollupOptions: {
          // 可以传递 Rollup 配置
          // output: {
          //   manualChunks(id) { // 自定义代码分割逻辑
          //     if (id.includes('node_modules')) {
          //       return 'vendor';
          //     }
          //   }
          // }
        },
      },
      css: {
        // CSS 相关配置
        modules: {
          // CSS Modules 配置
          localsConvention: "camelCaseOnly",
        },
        preprocessorOptions: {
          // CSS 预处理器选项
          scss: {
            // additionalData: `@import "@/styles/variables.scss";` // 全局注入 SCSS 变量
          },
        },
      },
    });
    • Vite 对资源的处理方式：
      • CSS: 直接导入即可，支持 @import，CSS Modules (.module.css)，预处理器 (需安装依赖 sass, less 等)。
      • 静态资源: 放在 public 目录下的文件会被直接复制到 dist 根目录；通过 JS 导入的资源 (e.g., import img from './img.png') 会被处理并得到解析后的 URL。
      • JSON: 直接导入会得到解析后的对象。
      • WebAssembly (Wasm): 有内置支持。
      • TypeScript: 开箱即用，Vite 使用 esbuild 转译，只做语法转换，不做类型检查 (推荐结合 tsc --noEmit 单独检查)。

b. Rollup​

  • 核心思想：专注于打包 JavaScript 库 (libraries)，尤其擅长输出扁平化的 ES Modules (ESM) 包，其 Tree Shaking 能力非常出色。Vite 在生产构建时就使用了 Rollup。

  • 特点：

    • 输出更干净、更小的代码，特别适合构建供其他项目使用的库。
    • 对 ESM 支持极好，Tree Shaking 效果显著。
    • 配置相对 Webpack 简单，但比 Parcel 复杂。
    • 插件系统健壮 (与 Vite 兼容)。
    • 不像 Webpack 那样内置开发服务器或 HMR (需要插件)。

  • 示例 (rollup.config.js): 构建一个简单的库

    npm install rollup @rollup/plugin-node-resolve @rollup/plugin-commonjs @rollup/plugin-babel @babel/core @babel/preset-env --save-dev
    // src/index.js (库入口)
    import { helper } from "./helper";
    export const mainFunction = (value) => {
      console.log("Main function called with:", value);
      return helper(value);
    };
    export const unusedFunction = () => {
      // 会被 Tree Shaking 掉 (如果未使用)
      console.log("This should be removed");
    };
    // src/helper.js
    export const helper = (input) => {
      return `Helper processed: ${input}`;
    };
    // rollup.config.js
    import resolve from "@rollup/plugin-node-resolve"; // 解析 node_modules 中的模块
    import commonjs from "@rollup/plugin-commonjs"; // 转换 CJS 模块为 ESM
    import babel from "@rollup/plugin-babel"; // 使用 Babel 转译

    export default {
      input: "src/index.js", // 入口文件
      output: [
        {
          // 输出 ESM 格式
          file: "dist/bundle.esm.js",
          format: "es", // ES Module 格式
          sourcemap: true,
        },
        {
          // 输出 CommonJS 格式
          file: "dist/bundle.cjs.js",
          format: "cjs", // CommonJS 格式
          sourcemap: true,
        },
        {
          // 输出 UMD 格式 (可在 <script> 标签或 AMD/CJS 环境使用)
          file: "dist/bundle.umd.js",
          format: "umd",
          name: "MyLibrary", // UMD 模式下挂载到 window 的全局变量名
          sourcemap: true,
          globals: {
            // 如果有外部依赖，UMD 需要指定全局变量名
            // 'lodash': '_'
          },
        },
      ],
      plugins: [
        resolve(), // 查找并打包 node_modules 中的依赖
        commonjs(), // 将 CommonJS 模块转换为 ES6，供 Rollup 处理
        babel({
          // 配置 Babel
          babelHelpers: "bundled", // 将 Babel helpers 内联到 bundle 中
          exclude: "node_modules/**", // 仅编译我们的源代码
          presets: ["@babel/preset-env"],
        }),
      ],
      // external: ['lodash'] // 如果不想打包某些依赖，将其标记为外部依赖
    };
    // package.json scripts
    "scripts": {
      "build": "rollup -c" // 使用配置文件进行构建
    },
    // 指明不同格式的入口
    "main": "dist/bundle.cjs.js", // CommonJS 入口
    "module": "dist/bundle.esm.js", // ESM 入口
    "browser": "dist/bundle.umd.js" // UMD 入口 (可选)

c. Parcel​

  • 核心思想：零配置 (Zero Configuration) 的 Web 应用打包器。旨在提供极简的开箱即用体验。
  • 特点：
    • 几乎无需配置，能自动检测入口文件类型 (HTML, JS, CSS 等) 并处理依赖。
    • 内置了对常见文件类型 (JS, TS, CSS, HTML, 图片等) 的转换和优化。
    • 自带开发服务器和 HMR。
    • 构建速度通常比 Webpack 快 (利用了多核处理)。
    • 对于简单项目或快速原型开发非常方便。
    • 当需要深度定制时，配置不如 Webpack 或 Rollup 灵活。
  • 示例: 
    npm install --save-dev parcel
    # 假设已有 src/index.html, src/index.js, src/styles.css
    <!-- src/index.html -->
    <!DOCTYPE html>
    <html>
      <head>
        <title>Parcel App</title>
        <link rel="stylesheet" href="styles.css" />
      </head>
      <body>
        <h1>Hello Parcel!</h1>
        <script type="module" src="index.js"></script>
        <!-- 必须指定 type="module" -->
      </body>
    </html>
    // src/index.js
    import "./message.js"; // 导入 JS 模块
    console.log("Hello from index.js");
    // src/message.js
    import { upperCase } from "lodash-es"; // 导入 npm 包
    console.log(upperCase("message from message.js"));
    /* src/styles.css */
    body {
      background-color: papayawhip;
    }
    h1 {
      color: tomato;
    }
    // package.json scripts
    "scripts": {
      "start": "parcel src/index.html", // 启动开发服务器
      "build": "parcel build src/index.html" // 构建生产版本
    }
    // 无需 parcel.config.js !
    // 如果需要自定义，可以创建 .parcelrc 文件

d. esbuild​

  • 核心思想：一个用 Go 语言编写的极速 JavaScript 打包器和压缩器。其核心目标是追求极致的构建速度。

  • 特点：

    • 比基于 JavaScript 的打包器 (Webpack, Rollup, Parcel) 快 10-100 倍。
    • 支持 JS, TS, JSX 的打包、压缩和转译。
    • 支持 Tree Shaking, Source Maps, Code Splitting (有限)。
    • 提供 CLI 和 JavaScript API。
    • 插件系统相对不成熟，生态不如 Webpack/Rollup 丰富。
    • 常被用作其他工具的底层引擎 (如 Vite 的开发服务器和 TS/JSX 转译，Jest 的代码转换)。

  • 示例 (CLI):

    npm install --save-dev esbuild
    # 打包单个文件，输出 IIFE 格式 (可在浏览器 <script> 中运行)
    npx esbuild src/index.js --bundle --outfile=dist/bundle.js --format=iife

    # 打包并压缩
    npx esbuild src/index.js --bundle --minify --outfile=dist/bundle.min.js

    # 打包为 ESM 格式
    npx esbuild src/index.js --bundle --outfile=dist/bundle.esm.js --format=esm

    # 同时处理多个入口点 (代码分割)
    npx esbuild src/pageA.js src/pageB.js --bundle --outdir=dist --splitting --format=esm

    # 处理 TypeScript
    npx esbuild src/index.ts --bundle --outfile=dist/bundle.js

    # 处理 JSX (需要指定 loader 和 jsx factory/fragment)
    npx esbuild src/app.jsx --bundle --outfile=dist/app.js --loader:.jsx=jsx --jsx-factory=React.createElement --jsx-fragment=React.Fragment

  • 示例 (JavaScript API):

    // build.js
    const esbuild = require("esbuild");
    const fs = require("fs");

    async function runBuild() {
      try {
        const result = await esbuild.build({
          entryPoints: ["src/index.js"], // 入口文件
          bundle: true, // 打包依赖
          outfile: "dist/bundle.js", // 输出文件
          minify: true, // 压缩代码
          sourcemap: true, // 生成 Source Map
          format: "esm", // 输出格式 (esm, cjs, iife)
          // splitting: true, // 启用代码分割 (需要 format='esm' 和多个入口或动态 import)
          // outdir: 'dist', // 与 splitting 配合使用
          target: ["es2020", "chrome58", "firefox57", "safari11", "edge16"], // 转译目标环境
          loader: {
            // 配置不同文件类型的加载器
            ".png": "dataurl", // 将 png 转为 data URL
            ".svg": "text", // 将 svg 作为文本导入
          },
          define: {
            // 定义全局常量 (替换代码中的标识符)
            "process.env.NODE_ENV": '"production"',
            __API_URL__: '"https://api.example.com"',
          },
          // external: ['react', 'react-dom'], // 标记外部依赖
          // plugins: [myPlugin()], // 使用插件
        });
        console.log("Build finished successfully.");
        // console.log('Output files:', result.outputFiles); // 如果 write: false, 可以从这里获取结果
      } catch (error) {
        console.error("Build failed:", error);
        process.exit(1);
      }
    }

    runBuild();
    // package.json scripts
    "scripts": {
      "build": "node build.js"
    }

四、 如何选择构建工具？​

选择哪个构建工具取决于项目需求、团队熟悉度和特定场景：

  • 大型复杂应用 (SPA), 需要高度定制化: Webpack 仍然是功能最全面、生态最强大的选择，虽然配置复杂，但能满足几乎所有需求。
  • 追求极致开发体验和速度 (尤其是中大型项目): Vite 是当前非常热门的选择，其开发服务器速度极快，配置相对简单，生产构建使用 Rollup 保证优化。特别适合 React, Vue, Svelte 等现代框架。
  • 构建 JavaScript 库 (Library): Rollup 是理想选择，其对 ESM 的优化和 Tree Shaking 能力非常出色，能生成干净、高效的包。
  • 快速原型开发、简单项目、追求零配置: Parcel 非常方便，上手快，能快速启动项目。
  • 需要极速的 JS/TS 编译/压缩环节，或作为底层工具: esbuild 本身可用于简单的构建任务，或者集成到其他工具链中（如 Vite, Jest）以加速特定步骤。
  • 旧项目维护或特定任务自动化: Grunt/Gulp 可能仍在一些旧项目或特定场景（如纯粹的任务流）中使用，但新项目较少选用。

五、 未来趋势​

  • Rust/Go 等原生语言工具链: 以 esbuild (Go) 和 SWC (Rust) 为代表，利用原生语言的高性能优势，未来可能会有更多基于 Rust/Go 的工具出现（如 Turbopack）。
  • 进一步利用原生 ESM: 随着浏览器和 Node.js 对 ESM 的支持越来越完善，构建工具会更深度地利用原生 ESM 的能力，减少转换和打包的复杂性。
  • 配置简化与约定优于配置: 类似 Vite 和 Parcel 的思路，提供更多开箱即用的功能和更智能的默认配置，减少开发者的配置负担。
  • 构建工具链的整合: 可能会出现更一体化的解决方案，覆盖从开发、构建到测试、部署的整个流程。
  • 边缘计算/Serverless 构建: 构建过程可能与部署环境更紧密地结合。
